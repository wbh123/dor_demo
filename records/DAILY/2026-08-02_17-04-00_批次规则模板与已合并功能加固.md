## 2. 关键决策

- 旧分支使用`V9__add_batch_rule_templates.sql`，与主分支现有V9冲突，因此以最新主线为基础改用V10；
- 批次规则模板采用不可变修订，不能覆盖历史记录；
- 批次保存精确`rule_template_id`，同时继续保存规则执行快照；
- 运行中的业务只读取批次快照，不动态读取模板；
- 新启用模板允许组队时人数范围为2至5，不允许组队时固定为1人；
- 历史批次规则迁移为停用模板，允许保留旧人数上限，但不能用于新批次；
- GitHub Actions不可用，不使用一次性工作流生成数据库固化文件；
- `backend-java/docs/sql/schema.sql`和`frontend/src/api/schema.ts`由本地验证流程重新生成；
- 队伍仍存在Redis临时床位占用时，不直接重开队伍，而是返回稳定冲突并要求先释放；
- 国际化保留现有渐进式翻译方案，但必须区分翻译器自身写入和Vue响应式更新；
- 已执行的Flyway迁移不修改，欢迎语历史兼容通过新增V11处理。

## 4. 数据库与接口影响

### 数据库影响

- 正式迁移版本从V9增加到V11；
- 新增`batch_rule_template`；
- `selection_batch`新增可空`rule_template_id`并建立外键；
- 应用创建和复制批次必须写入模板主键；
- 开发测试重复迁移为历史直接插入的批次补齐模板引用；
- V11只修复已有欢迎语数据，不修改V1至V10。

### 接口影响

新增：

```text
GET  /api/v1/admin/batch-rule-templates
POST /api/v1/admin/batch-rule-templates
POST /api/v1/admin/batch-rule-templates/{templateId}/revisions
```

`BatchRequest`新增可选`ruleTemplateId`。旧客户端不提交时使用默认模板，旧规则字段保留为弃用兼容字段。

新增稳定错误码：

```text
BATCH_RULE_TEMPLATE_NOT_FOUND
BATCH_RULE_TEMPLATE_DISABLED
BATCH_RULE_TEMPLATE_CODE_CONFLICT
BATCH_RULE_TEMPLATE_VERSION_CONFLICT
BATCH_RULE_TEMPLATE_INVALID
BATCH_RULE_TEMPLATE_DEFAULT_REQUIRED
TEAM_HOLD_ACTIVE
```

## 7. 已知限制与本地后续

本地验证前必须先执行：

```bash
python scripts/db/build_frozen_baseline.py
cd frontend && npm install --no-audit --no-fund && npm run build
```

这会重新生成：

本地还需重点人工验证：

- 队伍取得床位占用后，成员变化返回`TEAM_HOLD_ACTIVE`；

- Vue接口数据更新后英文翻译不会恢复成旧文本；

- 带`OTHER`床架的历史床位不会被合并成上下铺；
- 创建新模板修订不会改变旧批次规则快照。
