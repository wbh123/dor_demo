## 3. 选寝模式

### 3.1 `ROOM` 模式

学生选择寝室后创建：

```text
room_assignment.assignment_status = ACTIVE
room_assignment.room_id = 选择的寝室
room_assignment.bed_id = NULL
room_assignment.source_selection_mode = ROOM
```

系统不随机分配床位。寝室成员入住后自行协商实际床位。

个人与队伍均支持选寝室。队伍必须整体进入同一寝室，事务中一次检查完整队伍容量，任一成员失败则整体回滚。

### 3.2 `BED` 模式

管理员只有在有效权限包含：

```text
P2_BED_SELECTION_MODE
```

时才能创建和发布选床模式批次。

学生端继续使用临时占用、释放和确认流程。确认成功后，在同一事务中同步为跨批次在住事实。

### 3.3 后端越权防护

新增统一选床资格守卫，个人和队伍占用/确认接口重新检查：

- 当前批次必须为 `BED`；
- 学生必须属于当前批次；
- 床位必须属于批次开放范围；
- 寝室必须被当前活动批次锁定；
- 性别必须符合；
- 国内生/国际生属性必须符合；
- 寝室不能存在实际床位未确认的在住学生；
- 学生不能已经存在其他有效寝室归属；
- 队伍床位必须属于同一寝室；
- 队伍床位数必须等于成员人数；
- 混合类别队伍只能选择混住宿舍。

释放接口仍允许清理已经存在的临时占用，不被新增资格守卫阻断。

## 4. 活动批次房间互斥

批次进入：

```text
PUBLISHED
OPEN
PAUSED
```

前执行图形化预检并获取 `active_batch_room_lock`。

同一寝室主键唯一，因此不能同时属于两个活动批次，也不能同时处于 ROOM 和 BED 模式。

批次进入：

```text
CLOSED
FINISHED
CANCELLED
```

后释放活动锁。

释放活动锁不结束学生在住状态。

## 5. 假空床冲突处理

统一规则：

```text
剩余寝室容量 = 房间容量 - ACTIVE 在住人数
```

真实可选床位：

```text
当前批次开放范围内的启用床位
- ACTIVE 且已确认的现实在住床位
```

寝室存在：

```text
ACTIVE AND bed_id IS NULL
```

的学生时：

- 仍可继续用于 ROOM 模式；
- 禁止用于 BED 模式；
- 发布预检返回 `ROOM_BED_MAPPING_REQUIRED`；
- 管理员必须先完成现实床位核对。

不通过随机预留床位或随机映射解决，避免系统床位与现实入住冲突。

## 6. 国内生与国际生

学生：

```text
DOMESTIC
INTERNATIONAL
```

寝室：

```text
DOMESTIC_ONLY
INTERNATIONAL_ONLY
MIXED
```

批次可图形化开启：

```text
国内生与国际生分开选寝
```

隔离关闭：

- 国内生可选国内生专用或混住；
- 国际生可选国际生专用或混住；
- 混合类别队伍只能选混住。

隔离开启：

- 国内生只能选国内生专用；
- 国际生只能选国际生专用；
- 混住宿舍不进入批次；
- 混合类别队伍不能邀请、锁定或选择。

专用宿舍限制始终有效，不能被批次开关覆盖。

## 7. 转学生

新增图形化录入向导：

```text
frontend/src/components/admin/TransferStudentWizard.vue
```

三种处理方式：

### 7.1 仅录入资料

创建学生档案和待激活账号，不建立寝室归属和批次资格。

### 7.2 直接安排入住

管理员选择符合性别和学生类别的寝室，可选具体床位：

- 不选床位：建立寝室归属，床位待确认；
- 选择床位：建立完整在住事实；
- 始终检查房间容量和实际床位占用。

### 7.3 加入现有批次

在同一事务中：

1. 创建学生档案；
2. 检查批次状态；
3. 检查学生是否已有在住记录；
4. 检查是否参加其他活动批次；
5. 按性别、学生类别、批次房间范围和选择模式计算可用名额；
6. 有足够合格容量时增加资格和活动学生锁；
7. 无合格容量时整个事务回滚，学生档案也不会单独残留。
