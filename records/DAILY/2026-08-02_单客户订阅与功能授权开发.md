# 2026-08-02 单客户订阅与功能授权开发记录

## 1. 用户要求

- 单一学校、单一客户部署，不开发多租户；
- 新增唯一 `SYSTEM_ADMIN`；
- 系统管理员只管理套餐、订阅、功能授权、配额和平台审计；
- 第一阶段基础功能粗粒度授权；
- 第二、第三阶段功能细粒度授权；
- 套餐和订阅采用不可变修订；
- 长期订阅无结束日期；
- 升级和降级立即生效；
- 功能和配额覆盖在升降级后保留；
- 降级后允许存量超额，但禁止继续新增；
- 已启动批次继续完成，紧急停止除外；
- 初始系统管理员为 `system_admin`，首次登录强制修改密码；
- 忘记密码通过本地脚本重置；
- 不通过 GitHub Actions 运行测试，最终由本地 Codex 验证。

## 5. 已知风险

- 平台控制器当前以 Spring MVC 直接实现，最终应根据项目 OpenAPI 生成规则改为实现生成接口；
- 平台 OpenAPI 已建立独立片段，但根契约合并必须在本地生成阶段完成；
- 平台路由文件已建立，但需要接入现有主路由实例；
- 请求拦截器可提供统一入口，但资源计数和批次快照仍必须放在真实业务事务中，不能只依赖拦截器；
- 固定期限自动到期的实时判定已在服务层设计，生成 `EXPIRED` 修订的定时任务尚需本地补齐和测试；
- 未映射业务接口应在本地覆盖检查中明确映射，禁止静默遗漏。

这些项目已完整写入最终 Codex 本地验证提示词，Codex 应修复后再提交 `dev`。
