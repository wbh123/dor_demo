# Navicat 数据库脚本

本目录中的全部脚本统一使用数据库：

```text
wust_dormitory
```

## Navicat 直接执行

### 初始化数据库架构

在同一个 Navicat 连接中，按文件名顺序执行 `01_数据库架构` 目录内的全部 SQL。

第一份脚本会执行：

```sql
DROP DATABASE IF EXISTS `wust_dormitory`;
CREATE DATABASE `wust_dormitory` ...;
USE `wust_dormitory`;
```

V17 恢复学生欢迎语和默认批次规则；V18 在空库缺少参考配置时初始化正式的已发布个人偏好问卷、问卷选项和启用的默认匹配方案。

最后一份脚本会写入 Flyway V18 基线，使应用后续可以从 V19 继续迁移。

完成架构导入后，执行：

```text
04_数据库完整性检查/00_修复并检查数据库完整性.sql
```

全部通过时最后一行状态应为：

```text
DB_INTEGRITY_OK
```

### 导入1000人干净数据

先完成数据库架构，再按文件名顺序执行 `02_1000人干净测试数据` 中的三份 SQL：

```text
00_使用统一数据库.sql
01_清空并导入1000人干净数据.sql
02_恢复必需系统配置.sql
```

主数据脚本内部会调用 `clear_1000_test_data()`，清空当前学校业务数据后重新生成：

- 1000名学生；
- 260间五人寝；
- 1300张床；
- 无批次、无在住、无床位分配。

第三份脚本用于兼容此前已经生成的旧版内联数据文件：如果欢迎语曾被旧清理逻辑删除，会幂等恢复 `STUDENT_WELCOME_MESSAGE`，并清理配置表中的无效管理员引用和历史配额告警。

三份数据脚本完成后必须再次执行：

```text
04_数据库完整性检查/00_修复并检查数据库完整性.sql
```

### 导入1000人真实业务数据

先完成数据库架构，再按文件名顺序执行 `03_1000人真实业务数据` 中的三份 SQL：

```text
00_使用统一数据库.sql
01_清空并导入1000人真实业务数据.sql
02_恢复必需系统配置.sql
```

主数据脚本同样会先清空学校业务数据，再生成正常业务状态下的乱序数据。完成后执行数据库完整性检查脚本。

## 数据库完整性检查范围

完整性脚本会先做幂等修复，再检查：

- V1～V18关键表、字段、索引和外键；
- 学生类别、选寝模式、跨批次在住等关键结构；
- 唯一系统管理员和中英文学生欢迎语；
- 功能权限目录、资源配额目录、默认套餐和当前订阅；
- 默认批次规则模板；
- 至少一份有可用题目的已发布个人偏好问卷；
- 已发布问卷的每个启用单选题均具有启用选项；
- 至少一个 JSON 配置合法的启用匹配权重方案；
- 配置创建人、学生专业、床位寝室、在住床位等孤儿引用；
- 活动学生锁、活动寝室锁与批次状态是否一致；
- 同一学生多条有效在住、同一床位多名住户等业务冲突。

检查失败时脚本会通过 `SIGNAL SQLSTATE '45000'` 停止，并直接给出缺失对象或冲突类型。

## 生成四个完全独立单文件

在仓库根目录运行：

```bash
python scripts/db/generate_navicat_sql.py
```

生成位置：

```text
backend-java/docs/sql/navicat/generated/
```

校验已生成文件是否最新：

```bash
python scripts/db/generate_navicat_sql.py --check
```

四个生成文件均不包含 MySQL 客户端 `SOURCE` 命令，可直接通过 Navicat 的“运行 SQL 文件”功能导入。生成器会读取 V1～V18 正式迁移、修复后的千人公共基础文件和完整性检查源文件。

推荐执行顺序：

```text
01_数据库架构.sql
02_1000人干净测试数据.sql 或 03_1000人真实业务数据.sql
04_数据库完整性检查.sql
```

## 安全警告

- 数据库架构脚本会删除整个 `wust_dormitory` 数据库；
- 两套测试数据会清空该数据库中的学校业务数据；
- 只能在开发或测试环境使用；
- 不要对生产数据库执行。
