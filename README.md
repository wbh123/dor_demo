# 武汉科技大学学生宿舍智能选择系统

> 仓库名称：`Wust-Dormitory-Select`  
> 当前阶段：准备阶段——工程检查与项目文档基线  
> 文档基线日期：2026-08-01

本项目面向高校学生宿舍分配与自主选寝场景，为学生提供自主选寝、随机选择、组队选寝和生活习惯匹配，为管理人员提供宿舍资源维护、批次规则配置、随机分配、过程监管、结果导出和异常调整能力。

系统的核心目标不是简单实现“抢床位”，而是在高并发选寝过程中保证：

- 同一床位不会被多人最终占用；
- 房间和床位状态能够及时同步；
- 学生个人选择、组队选择和随机分配可以共存；
- 分配规则、操作过程和最终结果可追溯；
- 不使用大语言模型，也能快速推荐生活习惯更接近的室友或寝室。

## 1. 核心业务闭环

```text
管理人员导入学生与宿舍资源
→ 创建选寝批次并配置开放范围、时间和规则
→ 学生完善个人资料和生活习惯问卷
→ 学生个人选寝、组队选寝或使用随机选择
→ Redis 临时占用候选床位
→ 房间级服务器发送事件推送状态变化
→ 学生确认提交
→ 数据库事务完成最终占用
→ 未完成学生进入统一随机分配或人工补充分配
→ 结果公示、导出、审计和异常处理
```

## 2. 当前角色

### 学生

- 登录并维护本人可编辑资料；
- 填写生活习惯问卷和床位偏好；
- 查看允许公开的楼栋、房间、床位和室友信息；
- 进行自主选择或随机选择；
- 创建、加入、退出和锁定选寝队伍；
- 查看选寝状态、操作结果和最终分配结果。

### 宿舍管理人员

现阶段将学院管理员与宿舍管理员合并为统一管理角色，负责：

- 学生、组织、楼栋、楼层、房间和床位资源管理；
- 选寝批次、开放范围、时间窗口和分配规则配置；
- 床位禁用、解锁、调整和异常处理；
- 未选学生随机分配与补充分配；
- 结果确认、导出、统计和操作审计。

## 3. 关键能力

- **自主选寝**：学生选择可用房间和床位，临时占用后确认提交；
- **随机选择**：学生在选寝页面一键获取符合约束且匹配度较高的候选床位；
- **统一随机分配**：对未主动完成选寝的学生按批次规则统一分配；
- **组队选寝**：学生提前组队，在容量和成员条件满足时统一选择房间或床位；
- **实时状态同步**：学生进入选寝页面后建立房间级服务器发送事件连接，离开页面时关闭，服务端通过心跳识别失效连接；
- **并发防冲突**：Redis 负责短时占用，关系数据库事务与唯一约束负责最终一致性；
- **生活习惯匹配**：通过硬约束过滤、问卷特征向量、加权相似度、房间聚合评分和缓存索引进行秒级推荐；
- **五人间建模**：支持三张上床下桌床位，以及同一床架上的上铺和下铺两个独立床位，共五个床位。

## 5. 总体架构边界

```text
Vue 3 前端
    ↓ REST + 服务器发送事件
Spring Boot 单体业务系统
    ├── 认证、权限和批次规则
    ├── 学生、组队、宿舍、房间和床位
    ├── 选寝、随机分配和匹配计算
    ├── 审计、统计和结果导出
    ├── MySQL：最终业务事实
    └── Redis：临时占用、热点状态和短期缓存
```

固定边界：

- 前端只调用 Spring Boot，不直接访问数据库或 Redis；
- Redis 中的临时占用不是最终选寝结果；
- 最终床位归属必须通过后端事务和数据库唯一约束确认；
- 系统按单实例部署设计，现阶段不引入注册中心、消息队列、复杂微服务或多实例一致性方案；
- 匹配推荐不依赖大语言模型，不把推荐分数解释为学生关系好坏的确定结论；
- 学生隐私字段必须按最小必要原则展示，不公开联系方式、证件信息和完整个人档案。

## 7. 构建入口

后端依赖父级物料清单工程，具体以 `backend-java/README.md` 为准。

```bash
mvn -f backend-java/pom.xml clean package -DskipTests
```

前端：

```bash
cd frontend
npm ci
npm run build
```

说明：当前提交重点建立文档和修正初始化目录，不代表完整构建、数据库和业务联调已经验收。
