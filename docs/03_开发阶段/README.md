## 3. 第一阶段实施顺序

1. 数据库和测试数据基线；
2. 统一响应、错误码、请求编号和认证；
3. 学生、组织和宿舍资源；
4. 批次、资格、问卷和匹配；
5. 个人临时占用和最终提交；
6. 房间级服务器发送事件；
7. 组队选寝；
8. 随机选择、统一随机分配、调整和导出；
9. 全链路验收和阶段冻结。

### 当前已完成

- Flyway V1第一阶段结构迁移；
- Flyway V2房间固定性别迁移；
- 30张第一阶段业务表；
- 520名合成学生；
- 64个男生五人间；
- 80个女生四人间；
- 144个房间和640个床位；
- 当前男女床位各320个；
- 数据生成、基线测试和固化工具；
- 数据库设计、数据字典和使用说明。

当前房型只是首版学校配置。数据模型支持后续男生、女生各自四人间和五人间混合，但每个房间始终固定为男寝或女寝。

## 4. 第一阶段范围

### 工程基础

- Flyway数据库迁移；
- 统一响应和错误码；
- 登录认证与角色权限；
- OpenAPI生成和一致性检查；
- 自动化测试和持续集成。

### 核心业务

- 学生和组织；
- 校区、楼栋、楼层、房间、床架和床位；
- 房型、容量、固定房间性别和床位布局；
- 批次、资格和楼栋/房间/床位开放范围；
- 问卷、特征和基础匹配；
- 个人选寝和Redis临时占用；
- 组队整体选寝；
- 学生随机选择；
- 未选学生统一随机分配；
- 服务器发送事件；
- 人工调整、结果导出和审计。

## 5. 第一阶段禁止扩张

- 不拆分微服务；
- 不引入消息队列和注册中心；
- 不实现多实例推送；
- 不接入大语言模型；
- 不实现完整换寝审批；
- 不用复杂运筹最优解阻塞核心交付；
- 不提前实现物联网和支付能力。

## 6. 第一阶段验收门禁

至少完成：

- 空库Flyway迁移和已有库升级测试；
- 后端单元和集成测试；
- Redis原子占用并发测试；
- 数据库唯一约束冲突测试；
- 男女房间和学生性别一致性测试；
- 四人间、五人间布局和容量一致性测试；
- 组队整体成功和整体失败测试；
- 服务器发送事件连接、心跳和重连测试；
- 匹配算法固定样例和性能测试；
- 前端类型检查、测试和生产构建；
- 主流程HTTP验收；
- 数据导入、随机分配和导出验收；
- 数据库固化SQL、实施记录和冻结说明。

## 7. 第二阶段

- 更丰富的筛选和推荐；
- 匹配冲突解释和权重界面；
- 复杂队伍异常处理；
- 批次复制和规则模板；
- 权限、限流、导入安全和审计强化；
- 索引、慢查询、Redis恢复和并发压测；
- 贪心与局部交换优化、公平性评估。

## 8. 第三阶段

根据学校真实需求选择：

- 换寝和调寝申请；
- 候补和自动补位；
- 邮件、短信或学校消息平台通知；
- 权限细分；
- 历史住宿和资源利用分析；
- 移动应用或小程序；
- 生产监控、备份和灾难恢复增强。

## 9. 阶段冻结规则

阶段冻结后：

- 已发布OpenAPI不得无兼容说明地破坏性修改；
- 已执行Flyway迁移不得直接修改；
- 第一阶段冻结时运行固化工具生成独立数据库结构SQL；
- 最终分配唯一约束不得弱化；
- 房间固定男寝或女寝规则不得弱化；
- Redis临时占用与数据库最终事实边界不得颠倒；
- 前端不得自行计算正式分配结果；
- 匹配算法版本变更必须可追溯。
