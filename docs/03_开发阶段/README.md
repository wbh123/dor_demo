## 2. 第一阶段最终范围

### 工程与数据

- OpenAPI驱动和自动生成；
- 统一响应、错误码、请求编号、认证和角色权限；
- Flyway V1至V4及固化数据库结构；
- 5个专业、520名合成学生、144个房间和640个床位；
- MySQL 8.4、Redis 7.4与完整持续集成。

正式迁移：

```text
V1__create_phase1_schema.sql
V2__enforce_fixed_room_gender.sql
V3__normalize_major_and_minimize_student.sql
V4__refine_questionnaire_and_active_batch_rules.sql
```

### 核心业务

- 专业、学生、楼栋、楼层、房间、床架和床位；
- 房型、容量、房间固定性别和批次可选范围；
- 问卷、三态吸烟偏好、特征、匹配排序与随机推荐；
- 个人床位占用、直接换床和最终确认；
- 邀请式组队、接受、成员确认和整体选寝；
- Three.js三维选床、下拉框联动与移动端适配；
- 房间级服务器发送事件；
- 统一分配、导出、人工调整与审计。

## 3. 第一阶段最终门禁

- OpenAPI引用、生成接口和Controller实现约束；
- Java 21 Maven全模块构建；
- Vue、TypeScript、Three.js和Vite生产构建；
- Redis原子占用、令牌校验和数据库唯一约束；
- 个人选寝、邀请式组队、人工调整和审计HTTP闭环；
- MySQL、Redis、Flyway和Spring Boot真实运行。

## 4. 第一阶段收尾结论

第一阶段：已完成并最终冻结。后续不得：

- 直接修改V1至V4；
- 无兼容方案地破坏已发布OpenAPI；
- 将Redis作为最终分配事实；
- 弱化学生/床位唯一约束和房间固定性别规则；
- 在前端展示队伍内部名称、编号或其他学生敏感信息。

本地开发数据推荐通过以下脚本从零重建：

```bash
bash scripts/dev/reset-local-environment.sh
```

正式应用只加载正式Flyway迁移；开发数据由MySQL客户端直接导入，不进入Flyway历史。

## 5. 第二阶段

第二阶段：开发中，按以下顺序推进：

1. **宿舍布局配置**：每个房间独立配置床位坐标、朝向和上下铺位置；
2. **匹配运营**：权重管理、冲突解释和推荐理由；
3. **活动复用**：批次复制、规则模板和复杂组队异常处理；
4. **质量与安全**：导入校验、审计强化、限流和权限；
5. **性能与恢复**：索引、慢查询、Redis恢复和并发压测；
6. **分配优化**：贪心与局部交换、公平性指标和对比评估。

第二阶段数据库变化从V5开始，并继续遵守OpenAPI先行、Flyway只增不改、事务化与审计要求。

## 6. 第三阶段

根据学校真实需求选择：

- 换寝和调寝申请；
- 候补和自动补位；
- 邮件、短信或学校消息平台通知；
- 权限细分；
- 历史住宿和资源利用分析；
- 移动应用或小程序；
- 生产监控、备份和灾难恢复增强。
