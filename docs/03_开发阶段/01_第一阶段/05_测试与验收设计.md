# 第一阶段测试与验收设计

## 1. 验收层级

第一阶段采用五层门禁：

```text
静态结构检查
→ OpenAPI生成和Java编译
→ 前端类型生成与生产构建
→ MySQL/Redis真实运行
→ 认证与选寝HTTP主流程
```

任一层失败均不得合并到`main`。

## 2. 静态自动化测试

### 2.1 基础设施

```bash
python -m unittest scripts/dev/test_infra_config.py -v
```

检查：

- Docker Compose服务范围；
- 环境变量；
- 健康检查；
- Redis和MySQL持久化；
- 启动、重建和停止脚本。

### 2.2 数据库

```bash
python -m unittest scripts/db/test_database_baseline.py -v
```

检查：

- V1至V3迁移存在且按顺序固化；
- 专业独立建模；
- 学生表最小化；
- 学号格式、唯一性和测试数据数量；
- 男生五人间和女生四人间当前测试布局；
- 房型混合扩展能力；
- 最终分配和有效队伍唯一约束；
- 开发测试数据与生成器一致。

### 2.3 OpenAPI

```bash
python -m unittest scripts/api/test_openapi_contract.py -v
```

检查：

- 主契约引用可解析；
- `operationId`唯一；
- Controller实现生成接口；
- Controller不手写路由注解；
- 示例接口和手写响应模型被移除。

### 2.4 后端源码约束

```bash
python -m unittest scripts/backend/test_phase1_source.py -v
```

检查：

- 仓库内固定父级物料清单；
- 无状态认证和角色隔离；
- Redis原子占用和令牌释放；
- 最终分配事务；
- 锁定队伍优先统一分配；
- 批次床位范围；
- 人工调整历史和审计；
- 确定性匹配；
- 房间级服务器发送事件和心跳；
- 学生表已删除字段不再被代码读取。

### 2.5 前端源码约束

```bash
python -m unittest scripts/frontend/test_frontend_baseline.py -v
```

检查：

- 开发和构建前生成OpenAPI类型；
- 登录、学生和管理员路由；
- 个人及队伍选寝；
- 实时推送；
- 管理员专业、学生、宿舍、批次、分配和调整页面；
- 模板页面已清理。

## 3. 构建验收

### 3.1 后端

```bash
mvn -f backend-java/pom.xml clean verify
```

必须完成：

- 主OpenAPI解析；
- `AuthApi`、`AdminApi`、`StudentApi`和`RealtimeApi`生成；
- DTO生成；
- 四模块编译和测试；
- 可执行Spring Boot程序打包。

### 3.2 前端

```bash
cd frontend
npm install
npm run build
```

必须完成：

- OpenAPI TypeScript类型生成；
- Vue TypeScript检查；
- Vite生产构建。

## 4. 真实运行验收

持续集成使用：

```text
MySQL 8.4
Redis 7.4
Java 21
Node.js 22
Python 3.12
```

运行步骤：

1. 启动MySQL和Redis服务容器；
2. 构建Spring Boot可执行程序；
3. 加载正式V1至V3迁移；
4. 显式加载开发测试数据；
5. 启动服务；
6. 等待健康检查为`UP`；
7. 查询Flyway历史、表结构和数据数量；
8. 执行HTTP主流程。

结构断言：

- Flyway最高正式版本为V3；
- `major`存在；
- `organization`不存在；
- `student`只有7个约定字段；
- 学生520人；
- 床位640个。

## 5. HTTP主流程

脚本：

```bash
python scripts/e2e/phase1_smoke.py
```

自动执行：

```text
服务健康检查
→ 管理员登录
→ 工作台、专业、学生、楼栋和房间查询
→ 草稿批次准备
→ 发布并开放批次
→ 学生账号激活和登录
→ 学生资料读取
→ 问卷读取和提交
→ 候选房间和床位读取
→ Redis床位临时占用
→ 数据库最终确认
→ 学生结果读取
→ 管理员分配查询
→ 人工调整到合法空床位
→ 学生结果再次读取
→ 审计日志验证
→ 管理员和学生退出
```

## 6. 并发与一致性验收

进入第一阶段冻结前，还应在本地或持续集成扩展测试：

- 100个请求竞争同一床位，只允许一个占用成功；
- 过期令牌不能确认；
- 非持有者不能释放；
- 队伍多个床位全部空闲才允许整体占用；
- 任一队伍成员或床位冲突时整个事务回滚；
- 数据库唯一约束阻止重复学生和重复床位分配；
- 人工调整目标床位被竞争占用时事务失败；
- Redis不可用时不允许绕过临时占用直接确认。
