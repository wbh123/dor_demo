# 第一阶段详细开发计划

> **执行方式：** 在同一功能分支持续实施，完成后通过Squash合并到`main`。  
> **目标：** 形成可运行的专业、学生、宿舍、批次、问卷、选寝、组队、随机分配、实时推送和管理闭环。  
> **技术栈：** Java 21、Spring Boot、MySQL 8.4、Redis 7、Flyway、Vue 3、TypeScript、Vite。

## 全局约束

- 单体后端，单实例部署；
- MySQL保存最终事实，Redis只保存令牌、临时占用和可重建缓存；
- 学生仅有学号、姓名、性别和专业编号；
- 男女不混住，房间性别固定；
- 当前男五人间、女四人间，数据模型支持后续混合房型；
- OpenAPI、实现、测试和文档同步；
- 开发阶段只新增Flyway迁移；
- 主分支通过Squash控制提交数量。

## 任务一：公共后端与认证

- 统一响应、业务异常、请求编号和全局异常处理；
- 基于Redis的Bearer令牌；
- 管理员登录、学生激活、登录、退出和当前用户接口；
- 管理员与学生权限拦截；
- 审计日志公共入口。

## 任务二：专业、学生与宿舍资源

- 专业查询、新增、修改和禁用；
- 学生查询、新增、修改和批量导入基础接口；
- 楼栋、房间、床位查询与维护；
- 房型、容量、性别和床位布局校验；
- 管理端资源统计。

## 任务三：批次、问卷和匹配

- 批次创建、发布、开放、暂停和关闭；
- 学生资格与宿舍范围配置；
- 问卷读取和答案提交；
- 确定性特征计算与房间匹配排序；
- 推荐结果提供匹配项和风险提示。

## 任务四：个人选寝与实时状态

- Redis原子临时占用、令牌校验、释放和过期；
- 数据库事务确认最终分配；
- 房间级服务器发送事件连接、快照、心跳和事件推送；
- 学生查看本人最终结果。

## 任务五：组队和随机分配

- 创建队伍、邀请、接受、拒绝、锁定和解散；
- 队伍成员性别、资格和容量校验；
- 学生随机候选；
- 管理员预演和正式执行剩余学生分配；
- 执行记录、结果明细和幂等控制。

## 任务六：前端闭环

- 登录与学生激活；
- 学生首页、问卷、房间列表、床位占用、队伍和结果页；
- 管理员首页、专业学生、宿舍资源、批次和随机分配页面；
- 统一API客户端、令牌状态和路由权限；
- 服务器发送事件订阅和断线刷新。

## 任务七：验收与冻结

- 后端构建、单元测试和数据库迁移验证；
- 前端类型检查和生产构建；
- HTTP主流程测试；
- 并发占用与唯一约束测试；
- 文档和实施记录更新；
- 第一阶段全部验收后生成固化SQL。
