# 第一阶段前端页面与交互设计

> 文档编号：DOC-PHASE1-UI-001  
> 状态：第一阶段冻结后的体验优化基线  
> 日期：2026-08-01

## 1. 技术边界

前端使用 Vue 3、TypeScript 5.9、Vite、Vue Router、Pinia、Axios 和 `openapi-typescript`。

固定规则：

- 开发和生产构建前自动读取后端主 OpenAPI 生成 TypeScript 类型；
- 所有业务请求经过统一请求客户端；
- 路由守卫区分管理员和学生；
- 房间变化通知到达后重新读取服务端结果；
- 学生页面不展示数据库名称、房间状态版本、批次编号或服务健康提示；
- 页面文案面向业务人员和学生，不解释实现技术。

## 2. 批次状态在界面中的含义

```text
草稿 DRAFT
→ 已发布 PUBLISHED
→ 选寝中 OPEN
↔ 已暂停 PAUSED
→ 已关闭 CLOSED
→ 分配中 ALLOCATING
→ 已完成 FINISHED
```

- **已发布**：学生可以看到选寝入口并填写或修改生活习惯问卷，但不能确认床位；
- **选寝中**：学生可以浏览房间、临时保留床位并最终确认；
- **已暂停**：临时停止新增选择，学生仍可查看已有信息；
- **已关闭**：学生选寝入口关闭，管理人员处理未选学生；
- **分配中**：正在执行统一分配；
- **已完成**：结果已经确定，学生查看住宿结果。

管理页面显示中文状态名称和中文操作，不直接使用英文状态作为按钮文本。

## 3. 公共布局

### 3.1 登录与激活

学生首次使用时输入12位学号、姓名和自定义密码激活账号，随后使用学号登录。

### 3.2 应用布局

桌面端使用侧边栏，移动端转为紧凑导航。顶部只显示当前业务区域标题，不显示“系统服务正常”等运行状态。

## 4. 学生端页面

### 4.1 选寝首页

学生首页只呈现一个当前选寝流程，不展示批次编号、英文状态和内部规则字段。

首页展示：

- 学号、姓名、性别和专业；
- 已填写的生活习惯问卷摘要；
- “填写问卷”或“修改问卷”入口；
- 当前是否可以进入选寝；
- 已经确认的楼栋、房间、床位和床位类型；
- 面向学生的简洁规则说明。

确认床位后返回首页，住宿结果立即出现在首页上方。

### 4.2 生活习惯问卷

- 动态读取题目和服务端配置的选项；
- 支持时间、整数和单选题；
- 必填项未完成时禁止提交；
- 已发布和选寝中允许保存修改；
- 暂停时可以查看但不能保存；
- 提交后重新计算匹配结果；
- 不显示特征键等技术字段。

“是否接受室友吸烟”固定显示三个单选项：

```text
接受
不接受
均可
```

### 4.3 候选房间

- 按匹配程度排序；
- 房间卡片采用紧凑布局，减少移动端占用高度；
- 展示楼栋、房间、房型、楼层和剩余床位；
- 已有人选择时，展示匿名室友偏好和已有室友人数；
- 匿名标签最多显示三个，不显示姓名、学号和完整问卷；
- 支持按楼栋或房间号搜索；
- 支持推荐当前可选房间；
- 队伍模式只展示能够容纳完整队伍的房间。

### 4.4 房间与床位可视化

床位页面使用轻量级CSS伪三维布局：

- 左侧显示房门入口；
- 右侧显示窗户；
- 五人间的窗边右侧为一组上下铺；
- 其他床位按上床下桌绘制；
- 床位仍使用原生按钮，支持键盘操作和状态文字；
- 房间状态版本只在后端内部维护，不显示在页面中。

床位状态：

```text
可选择
暂时被其他同学保留
已为当前学生保留
已有同学选择
暂不可用
```

个人模式：选择床位后立即短暂保留，并显示确认倒计时。队伍模式需要选满与成员人数相同的床位后整体保留。

### 4.5 我的队伍

支持创建队伍、邀请、接受或拒绝、锁定队伍以及整体选寝。队伍信息不改变学生首页的单一当前选寝流程。

### 4.6 住宿结果

最终结果页和首页均展示当前有效住宿结果，包括楼栋、房间、床位、床位类型和分配方式。推荐结果和未确认的床位不显示为最终结果。

## 5. 管理端页面

### 5.1 宿舍资源

- 楼栋统计；
- 房间列表；
- 楼栋和宿舍性别下拉框变化后立即刷新，无需点击筛选按钮；
- 点击编辑后打开居中遮罩层窗口；
- 点击遮罩、取消或关闭按钮可以退出；
- 修改房型、容量、固定性别、运行状态和备注；
- 修改必须填写原因。

### 5.2 选寝批次

- 页面顶部显示中文状态流程；
- “已发布”与“选寝中”含义明确区分；
- 操作按钮使用“发布活动”“开放选寝”“暂停选寝”“结束选寝”等中文文本；
- 统一分配先预演再正式执行；
- 同一学生不得同时属于两个已发布、选寝中或已暂停批次。

其他专业学生、分配调整和导出页面沿用第一阶段冻结设计。

## 6. 响应式设计

- 大屏使用多列卡片和完整房间场景；
- 中屏改为单列学生首页；
- 小屏房间卡片缩小内边距和间距；
- 320像素宽度下不出现页面级横向滚动；
- 伪三维床位按两列重新排列；
- 模态编辑窗口在移动端从页面底部展开；
- 关键确认按钮保持可见，不遮挡床位。

## 7. 前端构建

```bash
cd frontend
npm install
npm run dev
npm run typecheck
npm run build
```

`npm run dev` 和 `npm run build` 会先生成 `frontend/src/api/schema.d.ts`，该文件不得手工修改。
