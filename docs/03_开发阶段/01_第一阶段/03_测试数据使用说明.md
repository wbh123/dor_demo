# 第一阶段测试数据使用说明

## 1. 数据内容

当前合成数据按照学校现阶段需求生成：

- 520名学生，男女各260名；
- 8栋宿舍楼，男女各4栋；
- 32个楼层；
- 64个男生五人间；
- 80个女生四人间；
- 144个房间；
- 640个独立床位，男女各320个；
- 一个已发布问卷版本；
- 一个默认匹配权重方案；
- 一个草稿测试批次；
- 520条批次资格；
- 520条标准化生活习惯特征。

男生五人间当前布局：

```text
3个上床下桌
+ 1组上下铺
= 5个床位
```

女生四人间当前布局：

```text
4个上床下桌
= 4个床位
```

房型只是当前测试配置。正式数据模型允许后续按房间配置四人间、五人间等不同房型，但每个房间必须固定为男寝或女寝，不能男女混住。

学生姓名均采用“测试男生001”“测试女生001”等合成名称，不包含真实个人信息。

## 2. 学号规则

全部学号为12位数字，以2026开头：

```text
202600000001
...
202600000520
```

学号在测试数据内唯一，数据库也建立唯一约束。

## 3. 重新生成

```bash
python scripts/db/generate_development_data.py
```

生成文件：

```text
backend-java/server/src/test/resources/db/dev-migration/R__development_test_data.sql
```

生成器采用固定规则。相同版本代码每次生成的内容完全一致。

## 4. 自动化验证

```bash
python -m unittest scripts/db/test_database_baseline.py -v
```

测试检查：

- 520个学号均为12位数字且以2026开头；
- 学号不重复；
- 男女学生各260名；
- 男生五人间64个；
- 女生四人间80个；
- 男女床位各320个；
- 男生五人间为3个上床下桌加1组上下铺；
- 女生四人间为4个上床下桌；
- 所有房间性别固定为男寝或女寝；
- 数据结构支持未来四人间、五人间混合；
- 批次可以按房间配置可选范围；
- 数据库最终分配唯一约束存在；
- Flyway配置安全；
- 已提交测试数据与生成器输出一致；
- 固化工具只合并正式版本迁移。

## 5. 加载测试数据

根目录 `.env` 默认只执行正式结构迁移：

```properties
WUST_DORMITORY_FLYWAY_LOCATIONS=classpath:db/migration
```

在专用本地开发数据库中，可临时改为：

```properties
WUST_DORMITORY_FLYWAY_LOCATIONS=classpath:db/migration,filesystem:backend-java/server/src/test/resources/db/dev-migration
```

随后从仓库根目录启动应用。Flyway先执行正式版本迁移，再执行开发数据重复迁移。

开发数据重复迁移使用固定测试主键，并会清理对应合成数据后重新生成。因此：

- 只允许在专用本地开发数据库或自动化测试数据库使用；
- 不得在含真实业务数据的数据库中启用；
- 生产环境不得加入 `db/dev-migration`。

## 6. 测试账号

开发数据提供一个管理员账号：

```text
用户名：admin
密码：Dormitory@2026
```

密码使用 `{noop}` 形式，仅用于认证模块完成前的本地数据准备。认证模块开发时必须改为安全密码哈希，生产环境不得保留该账号或密码。

学生账户处于 `PENDING` 状态且没有初始密码，后续认证开发阶段再确定激活流程。

## 7. 管理员后续配置能力

正式宿舍资源管理功能需要支持：

- 为每个房间选择房型；
- 设置房间容量；
- 设置固定男寝或女寝属性；
- 维护房间内床位布局；
- 在选寝批次中分别选择男生、女生可选房间；
- 在房型混合时按具体房间开放，而不是只按楼栋开放。
