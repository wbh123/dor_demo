# 第一阶段测试数据使用说明

## 1. 数据内容

当前合成数据包括：

- 5个测试专业；
- 520名学生，男女各260名；
- 8栋宿舍楼、32个楼层；
- 64个男生五人间；
- 80个女生四人间；
- 144个房间；
- 640个独立床位，男女各320个；
- 一个已发布问卷版本；
- “接受、不接受、均可”三态吸烟偏好；
- 一个默认匹配权重方案；
- 一个测试批次和520条资格；
- 520条标准化生活习惯特征。

学生表只保存学号、姓名、性别和专业外键。姓名、问卷和特征全部为合成数据。

## 2. 学号与账号

学号为12位数字并以2026开头：

```text
202600000001
...
202600000520
```

管理员开发账号：

```text
用户名：admin
密码：Dormitory@2026
```

学生示例：

```text
学号：202600000001
姓名：测试男生001
```

学生初始账号状态为`PENDING`，没有统一初始密码。首次使用时应在激活页面输入学号、姓名和自行设置的密码。

## 3. 宿舍规则

男生五人间：

```text
3个上床下桌 + 1组上下铺 = 5个床位
```

女生四人间：

```text
4个上床下桌 = 4个床位
```

当前数据只是首版配置。数据模型允许未来按房间混合四人间和五人间，但每个房间必须固定为男寝或女寝。

## 4. 重新生成SQL

```bash
python scripts/db/generate_development_data.py
```

生成：

```text
backend-java/server/src/test/resources/db/dev-migration/R__development_test_data.sql
```

V4后的问卷收口脚本：

```text
backend-java/server/src/test/resources/db/dev-migration/R__zz_refine_development_questionnaire.sql
```

生成器使用固定规则，同一版本代码的输出可复现。

## 5. 推荐的从零重建方式

在项目根目录执行：

```bash
bash scripts/dev/reset-local-environment.sh
```

无人值守：

```bash
bash scripts/dev/reset-local-environment.sh --yes
```

脚本会：

1. 停止并删除本地MySQL、Redis数据；
2. 重新启动MySQL和Redis容器；
3. 使用Flyway容器只执行正式V1至V4；
4. 使用MySQL客户端直接导入开发测试数据；
5. 校验专业、学生、房间、床位、问卷和管理员账号；
6. 断言`flyway_schema_history`中不存在开发重复迁移。

脚本不会构建或启动前端、后端。

## 6. 为什么不再让Flyway加载开发数据

正式应用默认只加载：

```text
classpath:db/migration
```

不得再把`src/test/resources/db/dev-migration`加入后端Flyway位置。否则开发重复迁移会写入`flyway_schema_history`，后端恢复为正式迁移目录后会出现“已执行迁移无法在本地解析”的校验错误。

正确边界：

```text
Flyway：只管理正式结构迁移
MySQL客户端：导入本地开发测试数据
```

生产数据库严禁导入这些合成数据。

## 7. 自动化验证

```bash
python -m unittest scripts/db/test_database_baseline.py scripts/db/test_mysql_compatibility.py scripts/db/test_frozen_schema.py -v
```

验证内容包括：

- 520个学号格式与唯一性；
- 男女学生各260名；
- 5个专业及外键关系；
- 学生最小字段边界；
- 男五人间、女四人间与640个床位；
- 房间固定性别；
- 三态吸烟偏好；
- Flyway V1至V4；
- 固化`schema.sql`与正式迁移一致；
- 开发数据与生成器输出一致。

## 8. 数据删除警告

`reset-local-environment.sh`会永久删除：

```text
data/mysql
data/redis
```

仅允许在本地开发环境执行。含真实业务数据时不得使用。
