> 状态：第一阶段：已完成并最终冻结

## 1. 最终冻结范围

- OpenAPI驱动的认证、管理端、学生端和实时接口；
- 专业、学生、宿舍资源和选寝批次；
- 问卷、三态吸烟偏好、特征、匹配和随机推荐；
- 个人选寝、直接切换床位和邀请式组队；
- Redis临时占用、令牌与MySQL最终分配事务；
- 房间级服务器发送事件；
- 管理员统一分配、查询、导出、调整和审计；
- Vue学生端与管理员端；
- Three.js三维床位选择、下拉框联动和移动端适配；
- Flyway V1至V4、固化数据库结构和开发测试数据工具。

## 2. 冻结架构

```text
Vue 3 + TypeScript + Three.js
    ↓ REST / 服务器发送事件
OpenAPI 3契约
    ↓ 自动生成Java接口、数据传输对象和TypeScript类型
Spring Boot 4单体应用
    ├── MySQL 8.4：最终业务事实
    └── Redis 7.4：令牌、临时占用和可重建状态
```

不得绕过：

1. 新接口先修改OpenAPI；
2. Controller只实现生成接口；
3. 已执行Flyway迁移不得修改；
4. Redis不得作为最终分配事实；
5. 分配确认、统一分配和人工调整必须事务化；
6. 关键操作必须写入历史或审计；
7. 前后端构建和完整运行流程必须进入持续集成。

## 4. 最终业务修正

冻结前完成的收尾修正包括：

## 7. 已知边界与第二阶段入口

第一阶段数据库能保存床位类型、`position_index`和上下铺共享床架，但尚未保存逐房间三维坐标与朝向；管理端因此不能单独设置每个房间的布局或上下铺具体位置。

该能力作为第二阶段第一项实现：

- 使用V5或更高Flyway迁移；
- 增加逐房间床位坐标和朝向；
- 上下铺上下层必须共享平面位置与朝向；
- 管理端提供可视化布局编辑；
- 学生Three.js页面优先读取数据库布局，旧房间保留默认回退；
- 所有修改记录原因和审计。

第二阶段不得破坏第一阶段冻结接口、事务、唯一约束、性别规则和Redis/MySQL边界。
