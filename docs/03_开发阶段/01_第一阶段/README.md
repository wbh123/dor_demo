# 第一阶段：核心选寝闭环

> 状态：已完成并最终冻结  
> 开始日期：2026-08-01  
> 最终冻结日期：2026-08-01

## 1. 阶段目标与结论

第一阶段完成了可独立运行和验收的高校学生选寝闭环：

```text
资源准备
→ 批次配置
→ 学生问卷
→ 个人选择或邀请式组队
→ Redis临时占用
→ MySQL最终确认
→ 管理员统一分配
→ 查询、导出、调整和审计
```

第一阶段：已完成并最终冻结。第二阶段：开发中。

## 2. OpenAPI驱动边界

```text
领域OpenAPI文件
→ openapi-interface.yaml统一汇总
→ Maven OpenAPI Generator
→ 生成AuthApi、AdminApi、StudentApi、RealtimeApi
→ Controller实现生成接口
```

- Controller不得手写对外接口路径；
- 请求和响应模型由生成器产生；
- 前端构建前从同一契约生成TypeScript类型；
- 新增接口必须先修改OpenAPI并通过契约测试。

## 3. 最终业务能力

### 3.1 管理端

- 管理员认证与角色权限；
- 专业、学生和宿舍资源维护；
- 学生导入；
- 批次创建、准备和完整状态流转；
- 学生资格和楼栋、房间、床位开放范围；
- 统一分配预演与提交；
- 锁定小组优先且不拆散小组；
- 正式分配查询与CSV导出；
- 有原因的人工换床；
- 分配历史和操作审计。

### 3.2 学生端

- 账号激活、登录、退出和个人资料；
- 生活习惯问卷、三态吸烟偏好、结果查看和修改；
- 匹配排序、匿名室友偏好和随机推荐；
- Three.js三维床位选择、下拉框联动和移动端适配；
- 个人床位临时占用、直接切换和最终确认；
- 邀请式组队：输入12位学号发送邀请，系统内部自动建立小组；
- 邀请接受、成员确认、多床位整体占用和确认；
- 学生端不展示队伍名称和内部编号；
- 最终住宿结果查询。

### 3.3 实时与一致性

- Redis保存带令牌和过期时间的临时占用；
- Lua脚本校验令牌后释放或续期；
- MySQL唯一约束保证同批次学生和床位唯一；
- 同一学生同一时刻只能参加一个活动批次；
- 最终确认在事务中写入当前分配和历史；
- 房间级服务器发送事件推送状态变化和心跳。

## 4. 学生与宿舍数据边界

学生业务信息仅包括：

```text
学号
姓名
性别
专业编号
```

当前开发数据：

```text
专业：5
学生：520（男260、女260）
宿舍楼：8
楼层：32
男生五人间：64
女生四人间：80
房间：144
床位：640
```

男生五人间当前为3个上床下桌和1组上下铺，女生四人间为4个上床下桌。每个房间必须固定为男寝或女寝。

第一阶段床位三维位置仍由`position_index`映射，管理员尚不能逐房间保存三维坐标、朝向或上下铺具体位置。该能力列入第二阶段首项。

## 5. 数据库最终基线

正式迁移：

```text
V1__create_phase1_schema.sql
V2__enforce_fixed_room_gender.sql
V3__normalize_major_and_minimize_student.sql
V4__refine_questionnaire_and_active_batch_rules.sql
```

V4包含：

- “接受、不接受、均可”三态吸烟偏好；
- 同一学生只能参加一个活动批次的数据库锁表。

固化快照：

```text
backend-java/docs/sql/schema.sql
```

后续不得修改V1至V4；结构变化必须新增V5或更高版本并重新生成固化快照。

## 6. 本地开发数据

推荐从项目根目录执行：

```bash
bash scripts/dev/reset-local-environment.sh
```

脚本只操作MySQL、Redis和Flyway容器：

1. 删除本地MySQL与Redis数据；
2. Flyway只执行正式V1至V4；
3. 通过MySQL客户端直接导入测试数据；
4. 确保开发数据不写入`flyway_schema_history`。
