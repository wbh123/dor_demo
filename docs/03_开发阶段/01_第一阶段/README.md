# 第一阶段：核心选寝闭环

> 状态：已完成并冻结  
> 开始日期：2026-08-01  
> 冻结日期：2026-08-01  
> 功能分支：`feature/phase1-minimal-student-major`

## 1. 阶段目标

完成可独立运行和验收的高校学生选寝核心闭环：

```text
资源准备
→ 批次配置
→ 学生问卷
→ 个人或组队选择
→ Redis临时占用
→ MySQL最终确认
→ 管理员统一分配
→ 查询、导出、调整和审计
```

## 2. 已完成实施顺序

1. 数据库、专业和合成测试数据基线；
2. 统一响应、错误码、请求编号和认证；
3. 专业、学生和宿舍资源管理；
4. 批次、资格、问卷、特征和匹配；
5. 个人临时占用与最终提交；
6. 房间级服务器发送事件；
7. 组队邀请、锁定和整体选寝；
8. 随机推荐、统一分配、导出和人工调整；
9. 前端学生端与管理员端页面；
10. 全链路运行验收和数据库固化。

## 3. OpenAPI驱动边界

后端采用与城安智序一致的契约驱动模式：

```text
领域OpenAPI文件
→ openapi-interface.yaml统一汇总
→ Maven OpenAPI Generator
→ 生成AuthApi/AdminApi/StudentApi/RealtimeApi
→ Controller实现生成接口
```

固定要求：

- Controller不得手写接口路径注解；
- 请求和响应数据传输对象由生成器产生；
- 前端构建前从同一契约生成TypeScript类型；
- 新增接口必须先修改OpenAPI并通过契约测试。

## 4. 业务能力

### 4.1 管理端

- 管理员认证与角色权限；
- 专业、学生和宿舍资源维护；
- 学生导入；
- 批次创建、准备和状态流转；
- 楼栋、房间和床位范围；
- 统一分配预演与提交；
- 锁定队伍优先且不拆散队伍；
- 正式分配查询和CSV导出；
- 有原因的人工换床；
- 分配历史与操作审计。

### 4.2 学生端

- 账号激活、登录和退出；
- 查看个人资料和可参与批次；
- 填写生活习惯问卷；
- 查看匹配排序和随机推荐；
- 个人床位占用、释放和确认；
- 创建队伍、邀请、接受和锁定；
- 队伍多床位原子占用与整体确认；
- 查看最终分配结果。

### 4.3 实时与并发

- Redis保存带令牌和过期时间的临时占用；
- Lua脚本校验令牌后释放或续期；
- MySQL双唯一约束保证同批次学生和床位唯一；
- 最终确认在事务中写入当前分配和历史；
- 房间级服务器发送事件推送状态变化和心跳。

## 5. 学生与宿舍数据边界

学生业务信息仅包括：

```text
学号
姓名
性别
专业编号
```

当前房型验收数据：

```text
男生：五人间，3个上床下桌 + 1组上下铺
女生：四人间，4个上床下桌
```

房型、容量、床位布局和房间性别分开建模，可在后续阶段扩展，但男女不得混住。

## 6. 第一阶段数据规模

专业：5

## 8. 数据库冻结

正式迁移：

```text
V1__create_phase1_schema.sql
V2__enforce_fixed_room_gender.sql
V3__normalize_major_and_minimize_student.sql
```

固化快照：

```text
backend-java/docs/sql/schema.sql
```

生成方式：

```bash
python scripts/db/build_frozen_baseline.py
```

后续不得修改V1、V2和V3。结构变化必须新增Flyway版本迁移并重新生成快照。
