# 第一阶段实施记录

> 日期：2026-08-01  
> 本轮主题：数据库与测试数据基线  
> 分支：`feature/phase1-database-baseline`

## 1. 用户要求

- 先设计数据库结构；
- 生成至少满足500名男女学生住宿需求的宿舍、房间和床位数据；
- 生成对应学生数据；
- 学号必须为以2026开头的12位数字；
- 直接开始第一阶段开发；
- 开发同时补充文档；
- 开发阶段使用Flyway迁移；
- 第一阶段开发完毕后固化为独立SQL；
- 主分支新增提交数量不超过3个；
- 当前房型为男生五人间、女生四人间；
- 后期可能出现男女各自四人间和五人间混合；
- 男女不得混住；
- 每个房间固定具有男寝或女寝属性；
- 管理员可以分别设置选寝批次中的可选宿舍。

## 2. 本轮范围

本轮建立第一阶段数据库事实边界和可重复测试数据，不提前实现认证控制器、选寝接口或正式前端页面。

本轮属于第一阶段正式开发，不再属于准备阶段。

## 3. 已实现

### 3.1 正式数据库结构

- 30张第一阶段业务表；
- 用户、学生、组织和导入任务；
- 校区、楼栋、楼层、房间、床架和床位；
- 批次、资格、楼栋范围、房间范围和床位范围；
- 问卷、原始答案、学生特征和权重方案；
- 队伍、成员和邀请；
- 当前有效分配和分配历史；
- 随机分配执行和结果；
- 操作审计。

### 3.2 关键约束

- 学号12位数字约束；
- 学号全局唯一；
- 同一学生在同一批次最多属于一个有效队伍；
- 同一学生在同一批次最多一个当前床位；
- 同一床位在同一批次最多分配给一个学生；
- 房间性别只能为 `M` 或 `F`；
- 男女不得混住；
- 批次可以按楼栋、房间和床位精确配置可选范围。

### 3.3 房型扩展能力

当前测试配置：

```text
男生：64个五人间
女生：80个四人间
```

数据库将以下内容分别保存：

- 房型；
- 房间容量；
- 房间固定性别；
- 独立床位；
- 共享床架；
- 批次可选房间范围。

因此后续学校调整时，可以在不推翻数据模型的情况下配置男生、女生各自的四人间和五人间混合。

### 3.4 Flyway

正式迁移：

```text
V1__create_phase1_schema.sql
V2__enforce_fixed_room_gender.sql
```

开发数据迁移：

```text
R__development_test_data.sql
```

正式应用默认只加载正式迁移。开发数据必须显式启用，并且只能用于专用本地或自动化测试数据库。

### 3.6 工具与测试

- `scripts/db/generate_development_data.py`：确定性生成开发数据；
- `scripts/db/test_database_baseline.py`：验证学号、数量、房型、性别、床位布局和数据库约束；
- `scripts/db/build_frozen_baseline.py`：阶段冻结时合并正式版本迁移；
- MyBatis Generator已从示例表切换为第一阶段业务表；
- Spring Boot已配置Flyway校验和禁止清库。

## 4. 数据库固化决策

开发期间不持续手工维护一份独立完整SQL作为事实来源。

正确流程：

```text
Flyway版本迁移持续演进
→ 第一阶段全部功能开发
→ 空库和升级迁移验收
→ 第一阶段冻结
→ 运行固化工具
→ 生成独立schema.sql
```

当前 `backend-java/docs/sql/schema.sql` 仅保留阶段未冻结提示。第一阶段完成前不应作为初始化脚本使用。
