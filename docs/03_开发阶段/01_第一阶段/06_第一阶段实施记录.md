# 第一阶段实施记录

> 日期：2026-08-01  
> 状态：核心闭环已冻结，体验优化实施中  
> 当前分支：`feature/ux-selection-refinement`

## 1. 需求边界

### 1.1 学生与专业

学生业务信息只保留学号、姓名、性别和专业编号。已建立独立`major`表，学生通过`major_id`关联；账号通过`app_user.student_id`关联；批次住宿资格保存在`batch_student_eligibility`。

### 1.2 宿舍

- 当前男生五人间、女生四人间；
- 男生五人间为3个上床下桌和1组上下铺；
- 女生四人间为4个上床下桌；
- 房间固定为男寝或女寝；
- 管理员按批次配置楼栋、房间和床位范围；
- 数据模型支持后续男女各自四人间、五人间混合。

### 1.3 工程边界

- Spring Boot单体后端；
- Vue 3前端；
- MySQL保存最终事实；
- Redis保存令牌和临时占用；
- 房间级服务器发送事件推送；
- 生活习惯匹配使用可解释确定性算法；
- 所有接口采用OpenAPI契约驱动模式。

## 3. OpenAPI驱动实施

契约按照认证、管理端、学生端、实时推送和公共响应拆分，由`openapi-interface.yaml`统一汇总。生成`AuthApi`、`AdminApi`、`StudentApi`和`RealtimeApi`，Controller仅实现生成接口。前端通过`openapi-typescript`生成类型。

## 4. 后端功能

### 4.1 认证与权限

- 学生账号激活；
- 管理员和学生登录；
- Redis令牌；
- 无状态权限控制；

### 4.2 资源与批次

- 专业、学生、楼栋、房间和床位管理；
- 学生导入；
- 批次创建、准备和状态流转；
- 批次资格和可选范围；
- 房型、容量、性别和运行状态校验；
- 活动批次学生唯一约束；
- 状态切换、学生锁写入和锁释放位于同一数据库事务。

### 4.3 问卷与匹配

- 问卷版本、问题和选项；
- 学生答案提交；
- 标准化特征；
- 可解释标签；

- 三态吸烟偏好冲突判断；

### 4.4 个人与组队选寝

- Redis原子占用；
- 占用令牌、过期时间和安全释放；
- 个人床位确认；
- 队伍创建、邀请、接受和锁定；
- 队伍多床位原子占用与整体确认；
- 批次床位范围强制校验；
- 房间级实时更新。

### 4.5 分配与审计

- 锁定队伍优先的管理员统一分配；
- 分配预演和防重复提交；
- 正式分配查询；
- CSV导出；
- 有原因的人工换床；
- 分配历史、操作审计和房间实时事件。

## 5. 前端实施

### 5.1 管理端优化

- 宿舍资源筛选下拉框变化后立即刷新；
- 取消独立筛选按钮；
- 房间编辑使用遮罩层模态窗口；
- 批次状态和操作统一使用中文业务名称；
- 页面明确区分“已发布”和“选寝中”。

### 5.2 学生首页优化

- 只展示一个当前选寝流程；
- 不显示批次编号、英文状态和内部字段；
- 展示生活习惯问卷摘要；
- 提供填写或修改问卷入口；
- 确认床位后直接显示楼栋、房间和床位；
- 规则说明不出现数据库或缓存等技术内容；
- 移除“系统服务正常”提示。

### 5.3 房间与床位优化

- 移动端房间卡片缩小；
- 已有室友时显示匿名偏好标签；
- 不显示室友姓名、学号和完整问卷；
- 床位页面改为CSS伪三维房间布局；
- 左侧显示入口，右侧显示窗户；
- 五人间窗边右侧两个床位固定为上下铺；
- 房间状态版本不显示在前端。

## 8. 批次状态说明

```text
DRAFT       草稿，管理人员配置
PUBLISHED   已发布，学生可填写问卷，不能确认床位
OPEN        选寝中，允许选择和确认床位
PAUSED      已暂停，临时停止新增选择
CLOSED      已关闭，学生选寝结束
ALLOCATING  分配中，处理未选学生
FINISHED    已完成，结果确定
CANCELLED   已取消
```
