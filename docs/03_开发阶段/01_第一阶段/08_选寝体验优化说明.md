# 选寝体验优化说明

> 日期：2026-08-01  
> 适用版本：Flyway V4及以上

## 1. 最终调整

- 宿舍资源房间编辑使用遮罩层窗口；
- 楼栋和宿舍性别筛选切换后立即刷新；
- 管理端批次状态和操作使用中文业务名称；
- 学生首页聚合问卷偏好和住宿结果；
- 学生端不展示批次编号、房间状态版本和系统运行提示；
- 吸烟偏好为“接受、不接受、均可”三态；
- 房间卡片展示匿名室友偏好；
- 床位页面使用Three.js绘制入口、窗户、上床下桌和上下铺；
- 三维场景采用斜视相机，窗户正对入口，床位沿房间纵深方向排列；
- 下拉框与三维点击同等有效并双向联动；
- 点击另一空床位时自动释放旧床位并申请新床位；
- 释放成功显示3秒浮窗；
- 移动端降低渲染负担并使用紧凑布局和底部操作区；
- WebGL不可用时仍可通过下拉框完成选床；
- 组队改为输入学号直接邀请，系统内部自动建立小组。

## 2. 批次状态

| 状态 | 中文名称 | 业务含义 |
|---|---|---|
| `DRAFT` | 草稿 | 管理人员配置学生、宿舍和规则 |
| `PUBLISHED` | 已发布 | 学生可查看活动并填写或修改问卷，不能确认床位 |
| `OPEN` | 选寝中 | 学生可选择、临时保留并确认床位 |
| `PAUSED` | 已暂停 | 暂停新增选寝操作 |
| `CLOSED` | 已关闭 | 学生选寝结束，准备处理未选学生 |
| `ALLOCATING` | 分配中 | 管理人员执行统一分配 |
| `FINISHED` | 已完成 | 住宿结果已经确定 |
| `CANCELLED` | 已取消 | 活动终止 |

## 3. 活动批次唯一性

活动状态为：

```text
PUBLISHED
OPEN
PAUSED
```

同一学生同一时刻只能属于一个活动批次。V4新增`active_batch_student_lock`，以`student_id`主键作为唯一约束。

批次状态切换由`BatchLifecycleService`在同一事务中完成：

```text
进入活动状态
→ 写入全部有资格学生的唯一锁
→ 修改批次状态

离开活动状态
→ 修改批次状态
→ 删除该批次的学生锁
```

学生已经参加另一活动时，数据库拒绝重复锁并回滚状态切换。

## 4. 邀请式组队

学生不再主动创建命名队伍，也不查看队伍编号：

```text
输入队友12位学号
→ 发送邀请
→ 系统自动建立内部小组
→ 对方接受
→ 邀请发起人确认成员
→ 整体选择床位
```

内部小组名称和编号仅用于数据库关联、并发控制和审计，不返回到学生页面。待接受邀请不计入已确认成员人数。

## 5. Three.js床位布局

第一阶段使用`bed.position_index`和床位类型映射默认三维位置：

- 上床下桌和上下铺统一纵向排列；
- 上下铺上下层共享同一床架平面位置；
- 窗户位于入口正对面的后墙；
- 相机采用斜侧上方视角；
- 选择状态使用高对比床垫、发光和徽标表示。

第一阶段管理端不能逐房间设置坐标、旋转角或上下铺具体位置。该能力进入第二阶段宿舍布局配置。

## 6. 本地升级与测试数据

拉取代码并构建后端：

```bash
git pull
mvn -f backend-java/pom.xml clean package -DskipTests
java -jar backend-java/starter/target/Service.jar
```

需要从零创建本地数据库和合成数据时执行：

```bash
bash scripts/dev/reset-local-environment.sh
```

该脚本只操作MySQL、Redis和Flyway容器。Flyway只执行正式V1至V4，开发数据通过MySQL客户端直接导入，不写入Flyway历史。

生产环境不得导入开发数据。
