# 选寝体验优化说明

> 日期：2026-08-01  
> 适用版本：Flyway V4及以上

## 1. 本轮调整

- 宿舍资源房间编辑改为遮罩层窗口；
- 楼栋和宿舍性别筛选切换后立即刷新；
- 管理端批次状态和操作使用中文业务名称；
- 学生首页聚合问卷偏好和住宿结果；
- 学生端不展示批次编号、房间状态版本和系统运行提示；
- 吸烟接受偏好改为“接受、不接受、均可”三态；
- 房间卡片展示匿名室友偏好；
- 床位页面使用带入口、窗户和窗边上下铺的伪三维布局；
- 移动端缩小房间卡片并重新排列床位场景。

## 2. 批次状态

| 状态 | 中文名称 | 业务含义 |
|---|---|---|
| `DRAFT` | 草稿 | 管理人员配置学生、宿舍和规则 |
| `PUBLISHED` | 已发布 | 学生可查看活动并填写或修改问卷，不能确认床位 |
| `OPEN` | 选寝中 | 学生可选择、短暂保留并确认床位 |
| `PAUSED` | 已暂停 | 暂时停止新增选寝操作 |
| `CLOSED` | 已关闭 | 学生选寝结束，准备处理未选学生 |
| `ALLOCATING` | 分配中 | 管理人员执行统一分配 |
| `FINISHED` | 已完成 | 住宿结果已经确定 |
| `CANCELLED` | 已取消 | 活动终止 |

## 3. 活动批次唯一性

活动状态包括：

```text
PUBLISHED
OPEN
PAUSED
```

同一学生同一时刻只能属于一个活动批次。V4新增`active_batch_student_lock`表，以`student_id`主键作为最终唯一约束。

批次状态切换由`BatchLifecycleService`在一个数据库事务中完成：

```text
进入活动状态
→ 写入全部有资格学生的唯一锁
→ 修改批次状态

离开活动状态
→ 修改批次状态
→ 删除该批次的学生锁
```

若学生已参加另一活动，数据库唯一约束会拒绝写入并回滚状态切换。该实现不依赖数据库触发器或超级管理员权限。

## 4. 本地升级

拉取代码并重新启动后端后，Flyway会自动执行V4：

```bash
git pull
mvn -f backend-java/pom.xml clean package -DskipTests
java -jar backend-java/starter/target/Service.jar
```

开发测试数据库需要加载合成数据时，保持：

```properties
WUST_DORMITORY_FLYWAY_LOCATIONS=classpath:db/migration,filesystem:backend-java/server/src/test/resources/db/dev-migration
```

生产数据库不得加载`db/dev-migration`目录。
