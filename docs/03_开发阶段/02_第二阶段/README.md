## 3. 已完成子项目：逐房间床位布局配置

管理员现在可以为每个房间独立设置床位平面坐标和朝向，并在学生Three.js选床场景中显示相同布局。

### 3.1 数据库

Flyway V5新增：

```text
room_bed_layout
├── bed_id
├── layout_x
├── layout_z
├── rotation_degrees
├── updated_by
├── version
├── created_at
└── updated_at
```

固定规则：

- 不回写第一阶段`bed`表；
- 没有自定义记录时继续使用`position_index`默认映射；
- 坐标限制在房间可视区域；
- 朝向只允许`0、90、180、270`度；
- 上下铺上下层共享平面坐标和朝向，高度仍由`bed_type`确定；
- 房间版本用于乐观锁，但不显示在页面上；
- 保存必须填写修改原因并写入审计。

### 3.2 OpenAPI与后端

新增：

```text
GET /api/v1/admin/rooms/{roomId}/bed-layout
PUT /api/v1/admin/rooms/{roomId}/bed-layout
```

`RoomLayoutService`负责：

- 默认布局计算；
- 房间床位完整性校验；
- 坐标和朝向校验；
- 上下铺床架一致性校验；
- 房间版本冲突处理；
- 布局批量保存和审计。

学生房间接口通过独立`StudentRoomLayoutService`合并自定义布局，不改变第一阶段床位占用与确认事务。

### 3.3 管理端

宿舍资源列表新增“布局”入口。编辑器支持：

- 俯视房间画布拖拽；
- 0.25单位吸附；
- 90度循环旋转；
- 同一上下铺床架整体移动；
- X、Z和朝向数值输入；
- 恢复默认布局预览；
- 修改原因；
- 桌面端和移动端适配。

### 3.4 学生端

Three.js场景：

- 优先读取`layout_x`、`layout_z`和`rotation_degrees`；
- 没有自定义布局时使用第一阶段斜视纵向默认布局；
- 上下铺共享床架锚点；
- 保留点击选择、下拉框联动、高亮和WebGL降级。

## 4. 配套修复

本地数据库重建脚本不再写死Flyway V4，而是扫描正式迁移目录并自动识别最新版本。新增V6及以后迁移时无需再次修改脚本。
