# 功能权限与业务接口映射

> 模式：单客户、单一学校部署  
> 系统管理员入口：`/api/v1/platform/**`  
> 业务入口：`/api/v1/admin/**`、`/api/v1/student/**`、`/api/v1/realtime/**`

## 1. 统一原则

- 系统管理员只能访问平台接口；
- 业务管理员和学生不能访问平台接口；
- 所有业务接口由 `FeatureAccessInterceptor` 和 `FeatureRouteCatalog` 统一检查；
- 第一阶段使用模块级权限；
- 第二阶段已实现增强操作使用具体操作权限；
- `READ_EXISTING` 在服务暂停、到期或终止时保留历史读取；
- `START_NEW` 使用当前订阅权限和服务状态；
- `CONTINUE_EXISTING_BATCH` 优先使用批次启动快照，但紧急停止始终拒绝；
- 前端隐藏不能替代后端校验。

## 4. 配额接入

| 配额代码 | 当前写入路径 |
|---|---|
| `MAX_STUDENTS` | 新增学生 |
| `MAX_CAMPUSES` | 新增校区 |
| `MAX_BUILDINGS` | 新增宿舍楼 |
| `MAX_ROOMS` | 新增房间 |
| `MAX_BEDS` | 新增床位 |
| `MAX_BATCHES_PER_YEAR` | 新建批次 |
| `MAX_CONCURRENT_ACTIVE_BATCHES` | 发布或打开批次，需在批次状态服务中完成事务内检查 |
| `MAX_IMPORT_ROWS_PER_JOB` | 导入预检后、落库前按实际行数检查 |
| `MAX_EXPORT_ROWS_PER_JOB` | 导出查询计数后、生成文件前检查 |

最后三项依赖实际业务服务中的数量和状态信息，必须在本地构建验收阶段确认已接入正确事务位置，不能只依赖请求拦截器。

## 5. 本地完整覆盖检查

本地 Codex 必须解析最终 OpenAPI 的全部 `operationId`，逐项核对：

1. 平台接口是否只允许 `SYSTEM_ADMIN`；
2. 业务接口是否映射到唯一功能代码；
3. 操作模式是否为 `READ_EXISTING`、`START_NEW` 或 `CONTINUE_EXISTING_BATCH`；
4. 新增资源是否关联配额；
5. 未映射接口是否应拒绝而不是静默放行；
6. 运行中批次快照是否在业务事务内创建和使用。
