# 功能权限与业务接口映射

> 模式：单客户、单一学校部署  
> 系统管理员入口：`/api/v1/platform/**`  
> 业务入口：`/api/v1/admin/**`、`/api/v1/student/**`、`/api/v1/realtime/**`

## 1. 统一原则

- 系统管理员只能访问平台接口；
- 业务管理员和学生不能访问平台接口；
- 所有业务接口由 `FeatureAccessInterceptor` 和 `FeatureRouteCatalog` 统一检查；
- 第一阶段使用模块级权限；
- 第二阶段已实现增强操作使用具体操作权限；
- `READ_EXISTING` 在服务暂停、到期或终止时保留历史读取；
- `START_NEW` 使用当前订阅权限和服务状态；
- `CONTINUE_EXISTING_BATCH` 优先使用批次启动快照，但紧急停止始终拒绝；
- 前端隐藏不能替代后端校验。

## 4. 系统管理平台图形化授权接口

系统管理员权限页面不再要求手工输入功能代码和 `GRANT`、`REVOKE`。前端读取后端计算完成的最终授权投影，并提交目标状态。

### 4.1 查询授权投影

```http
GET /api/v1/platform/features/entitlements?includeFuture=false
```

每项返回：

- 功能名称和功能代码；
- 第一、第二或第三阶段；
- 管理端、学生端或共享范围；
- 模块级或操作级粒度；
- 风险等级；
- 当前程序是否已经实现；
- 套餐默认是否开启；
- 最终有效状态；
- 当前覆盖类型；
- 授权来源；
- 最近一次覆盖时间。

授权来源固定为：

```text
PLAN_ENABLED
PLAN_DISABLED
OVERRIDE_GRANT
OVERRIDE_REVOKE
```

### 4.2 单项设置最终状态

```http
PUT /api/v1/platform/features/{featureCode}/state
```

请求示例：

```json
{
  "targetState": "ENABLED",
  "reason": "本次合同增补开放三维选床功能"
}
```

`targetState` 可选：

| 状态 | 含义 |
|---|---|
| `ENABLED` | 最终状态必须开启；套餐默认关闭时自动建立 `GRANT` |
| `DISABLED` | 最终状态必须关闭；套餐默认开启时自动建立 `REVOKE` |
| `INHERIT` | 终止当前有效覆盖，恢复套餐默认状态 |

后端负责推导覆盖类型，前端不得自行计算或直接操作覆盖记录。

### 4.3 批量设置最终状态

```http
POST /api/v1/platform/features/batch-state
```

请求示例：

```json
{
  "changes": [
    { "featureCode": "P2_BATCH_COPY", "targetState": "ENABLED" },
    { "featureCode": "P2_RULE_TEMPLATE_REVISE", "targetState": "DISABLED" },
    { "featureCode": "P2_ROOM_LAYOUT_VIEW", "targetState": "INHERIT" }
  ],
  "reason": "2026年秋季服务范围统一调整"
}
```

固定规则：

- 所有项目在同一数据库事务中执行；
- 任一功能无效、重复或尚未实现时整体回滚；
- 同一功能在一次请求中只能出现一次；
- 重复提交相同最终状态不会创建重复有效覆盖；
- 旧有效覆盖会被终止；
- 第三阶段未实现功能可以显示，但滑动开关必须禁用；
- 单项和批量操作都必须填写原因并写入平台审计。

### 4.4 图形界面行为

平台功能授权页面提供：

- 功能名称和功能代码搜索；
- 阶段筛选；
- 管理端、学生端和共享范围筛选；
- 开启、关闭、单独覆盖、套餐默认和未来功能筛选；
- 单项滑动开关；
- 单项变更原因确认框；
- 批量编辑模式；
- 分组全部开启、全部关闭和恢复套餐默认；
- 批量变更数量预览；
- 固定底部保存栏；
- 套餐默认、单独增补、单独移除和尚未实现状态标签。

## 5. 配额接入

| 配额代码 | 当前写入路径 |
|---|---|
| `MAX_STUDENTS` | 新增学生 |
| `MAX_CAMPUSES` | 新增校区 |
| `MAX_BUILDINGS` | 新增宿舍楼 |
| `MAX_ROOMS` | 新增房间 |
| `MAX_BEDS` | 新增床位 |
| `MAX_BATCHES_PER_YEAR` | 新建批次 |
| `MAX_CONCURRENT_ACTIVE_BATCHES` | 发布或打开批次，需在批次状态服务中完成事务内检查 |
| `MAX_IMPORT_ROWS_PER_JOB` | 导入预检后、落库前按实际行数检查 |
| `MAX_EXPORT_ROWS_PER_JOB` | 导出查询计数后、生成文件前检查 |

最后三项依赖实际业务服务中的数量和状态信息，必须在本地构建验收阶段确认已接入正确事务位置，不能只依赖请求拦截器。

## 6. 本地完整覆盖检查

本地 Codex 必须解析最终 OpenAPI 的全部 `operationId`，逐项核对：

1. 平台接口是否只允许 `SYSTEM_ADMIN`；
2. 业务接口是否映射到唯一功能代码；
3. 操作模式是否为 `READ_EXISTING`、`START_NEW` 或 `CONTINUE_EXISTING_BATCH`；
4. 新增资源是否关联配额；
5. 未映射接口是否应拒绝而不是静默放行；
6. 运行中批次快照是否在业务事务内创建和使用；
7. 图形化授权的单项和批量目标状态是否与最终有效权限一致。
