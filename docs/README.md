## 3. 文档优先级

发生冲突时按以下顺序判断：

1. 用户最近一次明确指令；
2. 根目录和子目录 `AGENTS.md`；
3. 当前阶段目录中的计划与验收文档；
4. 需求分析和系统设计文档；
5. OpenAPI、数据库迁移和当前代码事实；
6. README；
7. `records/` 中的历史记录。

历史文档不能覆盖新的明确决策。任何重要需求变化都应同步更新权威文档，而不是只记录在聊天、提交信息或临时笔记中。

## 5. 后续文档扩展规则

每个正式阶段应至少包含：

- `README.md`：阶段索引、状态和阅读顺序；
- 详细开发计划；
- 数据库与接口设计；
- 前端交互设计；
- 测试与验收设计；
- 实施与验收记录；
- 阶段冻结说明。

阶段完成后，稳定接口、数据库约束和关键业务规则必须冻结。后续修改需要说明原因、影响范围和兼容策略。
