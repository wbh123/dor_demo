# 批次规则模板实施计划

> 状态：源代码实现已提交，等待本地完整验证  
> 目标分支：`dev`  
> 验证方式：GitHub Actions不可用，使用本地Codex执行生成、构建、迁移和真实接口试验

## 1. 目标

实现可复用、可版本化和可审计的批次规则模板，并让新建和复制批次引用精确模板修订，同时继续保存独立规则执行快照。

## 2. 架构边界

- Flyway V10新增`batch_rule_template`不可变修订；
- `selection_batch.rule_template_id`引用精确修订；
- 批次继续保存占用、续期、组队、随机推荐和未选处理规则快照；
- 运行中的业务只读取批次快照，不动态读取模板；
- `BatchRuleTemplateService`与`BatchRuleTemplateController`负责模板运营；
- `BatchCreationService`负责从模板创建批次；
- `BatchCopyService`复制模板引用和规则快照；
- 管理端新增`/admin/rule-templates`页面。

## 3. 固定约束

- 不修改V1至V9；规则模板使用V10；
- 历史欢迎语兼容使用新增V11，不修改V9；
- 模板修订不可覆盖，只能创建新修订；
- 新启用模板允许组队时人数范围为2至5；
- 不允许组队时最小和最大人数均为1；
- 历史规则迁移为停用模板，可以保留旧上限，但不能用于新批次；
- 全库最多一个默认模板，默认模板必须启用；
- 新建批次显式选择模板；旧客户端未提交时使用默认模板；
- 批次复制同时复制模板主键和规则快照；
- 学生端不展示模板编号和修订；
- 所有模板写操作必须填写原因、使用事务并写审计。
