# 批次选择模式与管理员图形化界面设计

> **重要变更：** 本文中所有“ROOM 模式随机分配床位”的内容已经废止。最新有效规则以 `2026-08-02-international-separation-and-room-occupancy-design.md` 为准：ROOM 模式只记录寝室归属，不生成具体床位；存在未确认实际床位的在住学生时，该寝室禁止进入 BED 模式。

## 1. 背景与目标

现有系统默认按“学生进入寝室后选择具体床位”运行。新增需求要求同时支持：

- 选择寝室模式；
- 选择床位模式；
- 选择床位模式作为可独立授权的细粒度功能；
- 同一寝室在同一时间只能属于一个活动批次；
- 选择寝室后不分配具体床位，由学生线下协商并后续确认；
- 批次结束后，寝室可继续用于 ROOM 模式；只有实际床位全部确认后才可用于 BED 模式；
- 管理员端继续减少 JSON 输入和 JSON 原始展示；
- 平台功能授权卡片进一步缩小，提高同屏信息密度。

本设计保持单客户、单学校、单实例边界，不引入多租户字段或租户识别逻辑。

## 2. 术语与模式

批次选择模式固定为：

```text
ROOM：学生选择寝室，不生成具体床位
BED：学生选择具体床位
```

数据库字段使用 `selection_mode`，接口字段使用 `selectionMode`。

模式含义：

| 模式 | 学生可见操作 | 最终床位产生方式 |
|---|---|---|
| `ROOM` | 选择寝室 | 不自动产生床位，学生协商后自行或由管理员确认 |
| `BED` | 查看床位布局、临时占用、确认床位 | 学生确认具体床位 |

批次发布后不得修改选择模式。批次复制保留来源批次的选择模式，但新副本仍为草稿。

## 3. 功能权限设计

### 3.1 基础能力

`P1_SELF_SELECTION` 继续表示学生自选能力，包含选择寝室模式。

### 3.2 细粒度床位选择权限

新增功能代码：

```text
P2_BED_SELECTION_MODE
```

功能属性：

```text
phase = PHASE2
scope = SHARED
granularity = OPERATION
action_type = START_NEW
risk_level = MEDIUM
enabled_in_program = 1
```

规则：

1. 创建或发布 `ROOM` 批次只要求 `P1_SELF_SELECTION`；
2. 创建或发布 `BED` 批次同时要求：
   - `P1_SELF_SELECTION`；
   - `P2_BED_SELECTION_MODE`；
3. 前端根据有效权限决定模式卡片是否可选；
4. 后端在创建和发布两个时间点均重新校验，不能只依赖前端；
5. 现有批次迁移为 `BED`，以保持当前语义；
6. 当前默认完整套餐加入 `P2_BED_SELECTION_MODE`，避免升级后现有功能突然关闭；
7. 已经启动并拥有权限快照的 `BED` 批次继续按快照完成；紧急停止仍优先拒绝。

## 4. 数据库设计

新增 Flyway 正向迁移 `V15__add_batch_selection_modes.sql`，不得修改 V1 至 V14。

### 4.1 selection_batch

新增：

```sql
selection_mode VARCHAR(16) NOT NULL DEFAULT 'BED'
```

约束：

```sql
CHECK (selection_mode IN ('ROOM','BED'))
```

所有历史批次设置为 `BED`。

### 4.2 活动房间锁

新增表：

```text
active_batch_room_lock
```

字段：

| 字段 | 含义 |
|---|---|
| `room_id` | 房间主键，同时作为唯一占用键 |
| `batch_id` | 当前占用该房间的批次 |
| `selection_mode` | 锁定时的模式快照 |
| `locked_at` | 加锁时间 |

约束：

- `room_id` 唯一；
- 同一批次同一房间只能出现一条；
- 外键指向 `room` 和 `selection_batch`；
- 只表示活动批次资源占用，不表示学生分配。

### 4.3 ROOM 模式寝室归属

ROOM 模式使用独立寝室归属记录，不向 `bed_assignment` 随机写入床位。寝室归属跨批次持续有效，直到学生退宿、换寝或管理员结束在住状态。

详细模型、国际生隔离和床位确认流程见：

```text
2026-08-02-international-separation-and-room-occupancy-design.md
```

### 4.4 功能目录初始化

向 `feature_catalog` 增加 `P2_BED_SELECTION_MODE`，并加入默认完整套餐的当前修订。

## 5. 活动房间互斥

### 5.1 需要加锁的批次状态

以下状态视为活动状态：

```text
PUBLISHED
OPEN
PAUSED
```

选择在 `PUBLISHED` 时提前锁定房间，保证学生填写问卷和查看候选范围期间，房间不会被另一个批次抢占。

### 5.2 实际房间范围计算

发布前根据以下范围并集计算批次涉及的房间：

1. `batch_room_scope` 直接指定的房间；
2. `batch_building_scope` 指定楼栋下的启用房间；
3. `batch_bed_scope` 中床位所属的房间。

结果去重后写入 `active_batch_room_lock`。

### 5.3 加锁事务

批次从非活动状态进入活动状态时，在同一事务中：

1. 锁定批次记录；
2. 校验选择模式权限；
3. 计算房间范围；
4. 按房间编号稳定排序；
5. 插入活动房间锁；
6. 若任一房间已被其他活动批次占用，整体回滚；
7. 返回冲突批次和冲突房间的自然语言摘要；
8. 再更新批次状态。

错误代码：

```text
BATCH_ROOM_ACTIVE_CONFLICT
```

### 5.4 释放房间锁

批次从活动状态进入以下状态时释放：

```text
CLOSED
ALLOCATING
FINISHED
CANCELLED
```

释放活动锁不释放学生实际在住记录。后续批次仍需根据跨批次在住人数计算剩余容量，并在 BED 模式发布前检查所有实际床位是否已经确认。

## 6. ROOM 模式选择流程

个人选择寝室接口：

```http
POST /api/v1/student/batches/{batchId}/rooms/{roomId}/select
```

队伍选择寝室接口：

```http
POST /api/v1/student/batches/{batchId}/teams/{teamId}/rooms/{roomId}/select
```

两个接口只建立寝室归属，不随机分配床位。剩余容量按跨批次有效在住人数扣减。队伍选择时必须有足够容量容纳所有有效成员。

## 7. 选择床位模式保护

现有以下接口仅允许 `BED` 模式：

```text
查看床位布局
个人临时占用床位
释放个人占用
确认个人床位
队伍临时占用床位
释放队伍占用
确认队伍床位
三维床位选择
```

若批次为 `ROOM` 模式，返回：

```text
BATCH_SELECTION_MODE_MISMATCH
```

若目标寝室存在有效但未确认床位的在住学生，BED 模式发布必须返回：

```text
ROOM_BED_MAPPING_REQUIRED
```

## 8. 管理员和学生界面

管理员使用模式卡片、房间冲突预检、国际生隔离开关和在住床位确认页面，不使用 JSON。

ROOM 模式学生点击“选择此寝室”，确认文案为：

```text
确认后你将加入该寝室，系统不会分配具体床位。入住后请与室友协商床位，并按要求完成实际床位确认。
```

BED 模式继续使用当前床位布局、临时占用和确认流程。

## 9. 平台功能授权卡片缩小

`PlatformFeaturesView.vue` 调整为紧凑卡片：

- 桌面端默认三列；
- 取消固定最小高度；
- 减少卡片内边距；
- 功能名称、主要状态和滑动开关放在首行；
- 功能代码默认隐藏到详情；
- 批量编辑能力保持不变；
- 未来功能仍禁用。

## 10. 管理员页面去 JSON 化

套餐、订阅、配额、审计、批次预检、国际生隔离和在住床位确认均使用表单、卡片、进度条、表格、抽屉和床位图，不以原始 JSON 作为主要操作方式。

## 11. 最新验收标准

满足以下条件才可声明完成：

1. 管理员可图形化选择 ROOM 或 BED；
2. BED 模式受细粒度权限控制；
3. 同一寝室不能同时进入两个活动批次；
4. ROOM 模式只建立寝室归属，不产生随机床位；
5. 跨批次剩余容量按有效在住人数计算；
6. 存在未确认实际床位的寝室不能进入 BED 模式；
7. 学生或管理员可图形化确认实际床位；
8. 国内生、国际生和混住宿舍规则正确；
9. 批次可选择是否严格隔离国内生和国际生；
10. BED 模式只显示真实空床；
11. 管理员主要页面不依赖原始 JSON；
12. Maven、前端构建、数据库迁移和真实接口冒烟均有实际结果。
