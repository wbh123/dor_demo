# 第二阶段批次复制设计

## 1. 目标

管理员可从任意非“已取消”批次复制一份完整配置模板，以减少重复配置。复制后的批次始终为草稿，管理员必须重新填写唯一批次编码、批次名称、开始时间和结束时间。

## 2. 复制范围

复制以下配置事实：

- 问卷版本；
- 匹配权重方案的精确修订主键；
- 床位保留时长、续期次数；
- 是否允许组队、队伍最小和最大人数；
- 是否允许学生随机推荐；
- 未选学生处理策略；
- 规则版本；
- 楼栋开放范围；
- 房间开放范围；
- 床位开放范围。

不复制以下运行事实：

- 学生资格名单；
- 活动学生唯一锁；
- 组队、邀请和成员；
- Redis临时占用；
- 正式床位分配及历史；
- 分配运行记录；
- 原批次状态、发布时间和完成时间。

## 3. 接口

新增OpenAPI驱动接口：

```text
POST /api/v1/admin/batches/{batchId}/copy
```

请求字段：

```text
batchCode
batchName
startAt
endAt
reason
```

响应返回新批次编号、源批次编号以及复制的楼栋、房间、床位范围数量。

## 4. 校验

复制前在同一数据库事务内锁定源批次，并执行：

1. 源批次必须存在；
2. 源批次状态不能为`CANCELLED`；
3. 新批次编码必须唯一；
4. 新开始时间必须早于新结束时间；
5. 源批次必须引用有效问卷版本和匹配方案修订；
6. 源批次至少包含一种宿舍开放范围；
7. 楼栋范围中的楼栋必须启用；
8. 房间范围中的房间及其楼栋必须启用；
9. 床位范围中的床位、房间及其楼栋必须启用；
10. 发现异常资源时整体拒绝，不创建不完整副本，并返回可读异常清单。

## 5. 事务与审计

`BatchCopyService`负责校验和复制，全部写入位于一个MySQL事务内。新批次固定写入`DRAFT`。成功后记录`BATCH_COPY`审计，保存源批次、新批次、复制范围数量和修改原因。复制失败不留下半成品。

## 6. 管理端

批次卡片增加“复制配置”按钮，`CANCELLED`批次不显示。点击后打开遮罩层表单，展示源批次名称，要求填写新编码、新名称、新开始时间、新结束时间和复制原因。成功后关闭窗口、刷新列表，并明确提示只复制配置、不复制学生和结果。

移动端表单单列显示，操作按钮全宽，异常资源清单允许换行显示。

## 7. 错误码

- `BATCH_NOT_FOUND`：源批次不存在；
- `BATCH_COPY_CANCELLED_FORBIDDEN`：已取消批次禁止复制；
- `BATCH_CODE_CONFLICT`：新编码重复；
- `BATCH_TIME_INVALID`：时间范围无效；
- `BATCH_COPY_TEMPLATE_INCOMPLETE`：问卷、匹配方案或范围缺失；
- `BATCH_COPY_RESOURCE_UNAVAILABLE`：范围中存在停用、维护或不可用资源。

## 8. 测试

专项测试覆盖：

- OpenAPI契约和生成控制器签名；
- 成功复制全部配置及三类范围；
- 新批次固定为草稿；
- 学生资格、队伍、占用和分配不复制；
- 已取消批次、重复编码、无效时间、范围缺失和异常资源被拒绝；
- 事务回滚与`BATCH_COPY`审计；
- 管理端遮罩表单、移动端布局和错误反馈；
- MySQL、Redis、Spring Boot真实HTTP流程。
