# 国际生隔离与无固定床位寝室归属设计

> 本文覆盖并修正 `2026-08-02-selection-mode-and-admin-gui-design.md` 中“ROOM 模式随机分配床位”的旧设计。

## 1. 核心结论

`ROOM` 模式只确定学生属于哪个寝室，不分配具体床位。学生入住后可自行协商床位。

这会产生一个必须正面处理的问题：系统只知道寝室中有多少人在住，却不知道这些学生实际占用了哪几张床。如果此时直接把该寝室重新开放为 `BED` 模式，系统可能把现实中已经有人使用的床显示为空床。

因此采用以下强约束：

```text
存在“在住但床位未确认”的学生时：
- 该寝室可以继续用于 ROOM 模式，按剩余容量选寝；
- 该寝室禁止进入 BED 模式；
- 必须先完成实际床位确认，才可开放具体床位选择。
```

不采用“系统随便预留若干床位”或“随机把在住学生映射到床位”的方案，因为这仍可能与现实床位冲突。

## 2. 分清两类状态

### 2.1 活动批次房间锁

`active_batch_room_lock` 只解决“同一时间不能被两个活动批次同时选择”的问题。

锁在批次结束后释放，不代表房间内学生离开，也不代表床位重新空闲。

### 2.2 跨批次实际在住状态

`room_assignment` 升级为跨批次持续有效的实际在住记录，是房间容量和床位占用的真实来源。

记录至少包含：

```text
student_id
room_id
bed_id（可为空）
source_batch_id
source_selection_mode
team_id
assignment_method
assignment_status
assigned_at
bed_confirmed_at
ended_at
end_reason
```

语义：

- ROOM 模式选择成功：创建在住记录，`bed_id=NULL`；
- BED 模式选择成功：创建在住记录并写入具体 `bed_id`；
- 批次结束：在住记录继续有效；
- 学生退宿、换寝或管理员纠错：将记录结束，而不是删除；
- 同一学生只能有一条有效在住记录；
- 同一床位只能有一条有效且已确认的在住记录。

`bed_assignment` 可继续作为批次选床结果和历史兼容表，但房间剩余容量与跨批次床位占用统一以有效在住记录为准。

## 3. 房间剩余容量计算

所有模式统一使用：

```text
剩余容量 = 房间容量 - 当前有效在住人数
```

不能再只统计当前批次的 `bed_assignment`。

ROOM 模式允许选择的条件：

- 房间运行状态可用；
- 学生性别符合；
- 国际生/国内生规则符合；
- 房间属于当前批次范围；
- 剩余容量大于零；
- 没有被其他活动批次加锁。

队伍选择寝室时，剩余容量必须不少于有效队员人数。

## 4. BED 模式开放条件

房间进入 BED 模式前必须通过“床位可识别性检查”：

```text
当前有效在住人数中，bed_id 为空的人数必须为 0。
```

如果存在未确认床位的在住学生：

- 发布批次时整体拒绝；
- 管理员界面显示具体寝室和未确认人数；
- 错误代码：`ROOM_BED_MAPPING_REQUIRED`；
- 不向学生展示该寝室的床位图；
- 不允许通过床位范围绕过检查。

只有完成全部实际床位确认后，系统才可以准确计算：

```text
可选床位 = 启用床位 - 有效且已确认的在住床位
```

## 5. 实际床位确认流程

### 5.1 学生自主确认

ROOM 模式选寝结束后，学生协商完成可在系统中提交本人实际床位：

```http
POST /api/v1/student/residency/bed-confirmation
```

规则：

- 只能确认本人当前寝室内的床位；
- 床位必须启用；
- 床位不能已被其他有效在住记录占用；
- 并发选择同一床位时只允许一个成功；
- 确认后写审计与历史；
- 允许在管理员设置的确认截止时间前修改；
- 截止后只能由管理员调整。

### 5.2 管理员图形化核对

管理员提供“在住与床位确认”页面：

- 左侧显示未确认学生；
- 右侧显示寝室床位图；
- 支持拖拽学生到实际床位；
- 已占用床位显示学生姓名；
- 冲突床位禁止放置；
- 支持批量保存；
- 保存前显示未确认人数和冲突预览；
- 不使用 JSON 输入或展示。

管理员可用于：

- 学生未主动确认；
- 线下调床；
- 数据导入；
- 纠正错误确认；
- 开放 BED 模式前完成核对。

### 5.3 房间状态提示

房间增加派生状态：

```text
BED_MAPPING_COMPLETE：所有在住学生都有具体床位
BED_MAPPING_INCOMPLETE：存在未确认床位的在住学生
EMPTY：当前无人居住
```

管理员房间卡片直接显示：

```text
当前在住 4 人
已确认床位 2 人
待确认床位 2 人
可继续选寝 1 人
暂不可开放选床模式
```

## 6. 国际生与国内生模型

### 6.1 学生属性

保留 `nationality_code`，新增明确业务字段：

```text
student_category = DOMESTIC | INTERNATIONAL
```

迁移默认：

```text
nationality_code = CN -> DOMESTIC
其他 -> INTERNATIONAL
```

管理员可在学生编辑和导入页面显式修改，避免港澳台、双重国籍或特殊学籍仅靠国籍代码错误推断。

### 6.2 宿舍属性

房间新增：

```text
resident_scope = DOMESTIC_ONLY | INTERNATIONAL_ONLY | MIXED
```

管理员界面使用三段式图形控件：

- 国内生宿舍；
- 国际生宿舍；
- 混住宿舍。

默认 `MIXED`，保证历史房间兼容。

### 6.3 批次隔离开关

批次新增：

```text
separate_student_categories BOOLEAN
```

管理员创建批次时使用滑动开关：

```text
国内生与国际生分开选寝
```

默认关闭，避免历史数据迁移后所有 MIXED 房间无法发布。

## 7. 国际生隔离规则

房间自身限制始终有效：

- `DOMESTIC_ONLY`：仅国内生；
- `INTERNATIONAL_ONLY`：仅国际生；
- `MIXED`：可混住，但仅在批次关闭隔离时可用。

批次隔离关闭：

```text
国内生 -> DOMESTIC_ONLY 或 MIXED
国际生 -> INTERNATIONAL_ONLY 或 MIXED
```

批次隔离开启：

```text
国内生 -> 只能 DOMESTIC_ONLY
国际生 -> 只能 INTERNATIONAL_ONLY
MIXED 房间不得进入该批次范围
```

这样“可选是否隔离”和“国际生/国内生专用宿舍”同时成立，不会出现专用宿舍被另一类学生选择。

## 8. 队伍规则

隔离关闭时：

- 同类别队伍可选对应专用宿舍或 MIXED；
- 国内生与国际生混合队伍只能选择 MIXED。

隔离开启时：

- 队伍所有成员必须属于同一学生类别；
- 国内生队伍只能选 `DOMESTIC_ONLY`；
- 国际生队伍只能选 `INTERNATIONAL_ONLY`；
- 混合队伍不能锁定或参与选择。

错误代码：

```text
TEAM_STUDENT_CATEGORY_MISMATCH
ROOM_STUDENT_CATEGORY_MISMATCH
BATCH_MIXED_ROOM_FORBIDDEN
```

## 9. 发布前图形化预检

管理员点击发布前，界面展示四类检查：

1. 活动批次房间冲突；
2. 性别范围冲突；
3. 国际生/国内生隔离冲突；
4. BED 模式实际床位未确认冲突。

采用卡片和问题清单，不显示 JSON。

示例：

```text
南一栋 301：2 名在住学生尚未确认床位，不能用于选床模式
国际生公寓 202：当前批次仅包含国内生，不可加入
南二栋 405：正在被“2026级第一轮选寝”使用
```

发布按钮仅在全部阻断问题解决后启用。

## 10. 数据库迁移策略

V15 已经提交到 `main`，不回改已经发布的迁移。

新增 V16，完成：

- `student.student_category`；
- `room.resident_scope`；
- `selection_batch.separate_student_categories`；
- 扩展 `room_assignment` 为跨批次实际在住记录；
- 增加可空 `bed_id`；
- 增加结束状态和床位确认时间；
- 增加有效学生唯一约束；
- 增加有效床位唯一约束；
- 将现有有效 `bed_assignment` 回填为已确认床位的在住记录；
- 增加在住记录历史或审计字段；
- 增加发布预检所需索引。

## 11. 选寝与选床模式最终行为

### ROOM 模式

- 学生只选择寝室；
- 系统写入在住记录，`bed_id=NULL`；
- 不创建随机床位；
- 剩余容量按有效在住人数扣减；
- 学生线下协商床位；
- 后续可自主或由管理员确认床位；
- 未确认前，该寝室只能继续用于 ROOM 模式。

### BED 模式

- 只允许所有现有在住学生床位已确认的寝室；
- 学生查看并选择具体空床；
- 选床成功同时写批次床位结果和跨批次在住记录；
- 不能把未知占用的床错误显示为空床。

## 12. 验收关键场景

必须验证：

1. ROOM 模式学生选寝后 `bed_id` 为空；
2. 批次结束后在住记录仍保留；
3. 房间剩余容量跨批次正确扣减；
4. 未确认床位的房间可继续 ROOM 模式选剩余名额；
5. 未确认床位的房间发布 BED 批次被拒绝；
6. 学生确认实际床位后，唯一床位约束生效；
7. 全部床位确认后，房间可进入 BED 模式；
8. BED 模式只展示真实空床；
9. 国内生不能选择国际生专用宿舍；
10. 国际生不能选择国内生专用宿舍；
11. 隔离开启时 MIXED 房间不能进入批次；
12. 隔离关闭时 MIXED 房间可供两类学生选择；
13. 隔离开启时混合类别队伍被拒绝；
14. 管理员所有冲突和确认操作均使用图形界面。
