# 学生个人偏好、首次欢迎与房间筛选设计

## 目标

在不改变现有选寝核心事务的前提下，降低学生页面的信息占用，完整展示个人偏好和用户画像，突出选寝入口，精简三维选床提示，并增加可持久化、可配置的首次登录欢迎体验以及楼层、剩余铺位筛选。

## 学生首页

1. “我的生活习惯偏好”统一改名为“我的个人偏好”，项目内面向用户的“问卷”“生活习惯问卷”等文案统一替换为“个人偏好”或“偏好设置”。接口路径和数据库表名保持不变，避免无必要的兼容性改造。
2. 所有已填写偏好必须完整展示，不再截取前八项。
3. 偏好集中在一个大卡片中展示：上部为用户画像概述和画像标签，下部为紧凑的两列或多列键值列表，不为每个偏好创建独立卡片。
4. 用户画像由已有偏好确定性生成，不调用大模型。例如根据作息时间、睡眠敏感度、整洁要求、社交活跃度、学习频率和床位偏好生成一句概述，并生成最多六个短标签。画像仅用于展示，不参与匹配计算。
5. “选择宿舍和床位”“组队选寝”改为首页主要行动按钮，增大高度、字号和点击面积，并在个人偏好卡片下形成清晰的操作区。
6. 首页保留完整住宿结果和修改个人偏好入口，删除重复、冗长的说明文字，适当压缩欢迎区和卡片间距。

## 个人偏好扩展

空调偏好不再只使用一个笼统温度字段，而是拆分为：

- 夏季是否接受整夜开启空调制冷：不接受、接受定时、接受整夜开启、不在意；
- 夏季制冷温度；
- 冬季是否接受空调制热：不接受、接受、不在意；
- 冬季制热温度，仅在接受或不在意制热时显示并由前端动态设为必填。

同时加入三个高影响、低敏感度、容易引发真实室友冲突的维度：

- 室友休息或熄灯后的活动状态；
- 早晨闹钟是否反复响铃；
- 对宿舍内重气味食物的接受程度。

这些维度进入确定性匹配权重和公开推荐解释。系统不采集疾病、打鼾等敏感健康信息，也不根据偏好评价个人品质。

## 学生选床页面

1. 隐藏三维画布中的“开放视角”“门窗位于房间短边”“纵向2×2布局”提示。
2. 删除“窗户正对入口”“床位变化会自动更新”“C床与上下铺位于同一前排”等非必要布局说明。
3. 删除下拉框下方、未选择状态等重复的操作需求提示；保留必要控件名称、当前选中床位和临时保留倒计时。
4. 底部仅保留四个床位状态气泡：可选择、已选中、暂时保留、已有同学选择。
5. 团队模式的已选数量属于关键业务状态，继续保留。

## 学生顶栏

学生端不再显示独立的“学生选寝中心”大顶栏。管理员端继续显示“管理控制台”。学生页面直接使用各页面自身标题，减少首屏无效高度。

## 房间筛选

房间列表在现有搜索和组队人数限制基础上增加：

- 楼层筛选：选项从当前候选房间动态生成；
- 最少剩余铺位筛选：支持全部、至少1个、至少2个、至少3个、至少4个、至少5个；
- 搜索词、楼层、最少剩余铺位、组队人数限制同时生效；
- 无匹配结果时显示明确空状态；
- 筛选在前端即时完成，不新增后端查询参数。

## 首次登录欢迎

### 数据模型

新增数据库迁移：

- `app_user.welcome_acknowledged_at`：学生确认首次欢迎后的时间；
- `system_setting`：保存系统级配置，首期使用 `STUDENT_WELCOME_MESSAGE`，包含配置值、版本、修改人和修改时间；
- 默认欢迎文本为管理员未配置时的兜底值。

学生激活时将 `welcome_acknowledged_at` 置空。管理员账号和已经确认欢迎的学生不会弹窗。

### 接口

1. 登录响应和 `/api/v1/auth/me` 的当前用户信息增加可空 `welcome`：包含 `required`、`title`、`message`。
2. 新增 `POST /api/v1/auth/welcome/acknowledge`，仅学生可调用，幂等写入确认时间。
3. 新增管理员欢迎配置读取和更新接口。更新请求包含欢迎文本与版本号，使用乐观锁防止覆盖，并写审计日志。
4. 欢迎文本去除首尾空白，长度限制为1至1000个字符，不允许空文本。

### 前端交互

1. 学生首次激活后第一次成功登录，进入学生首页时显示全屏遮罩层。
2. 浮窗标题固定为“新同学，欢迎你”，正文来自管理员配置。
3. 浮窗采用轻量淡入、上浮和装饰光晕动画；遵守 `prefers-reduced-motion`，用户选择减少动画时关闭位移动画。
4. 用户点击“开始使用”后先调用确认接口，成功后关闭；失败时保留浮窗并显示错误，防止误认为已确认。
5. 页面刷新或换设备时，只要尚未确认，浮窗仍会再次出现；确认后永久不再出现，管理员修改文案也不会让老用户重复弹出。

## 管理端

在管理工作台增加“新生欢迎语”设置卡片：显示当前文案、最后修改时间，支持编辑和保存。无需增加独立导航页面。保存成功后刷新版本号并显示成功提示。

匹配规则页面增加新增个人偏好维度的权重输入。旧方案中的单一空调温度权重在编辑时兼容映射为夏季制冷温度，新修订使用细化后的权重集合。

## 测试与验收

1. 静态前端测试验证个人偏好完整展示、画像概述、主要按钮、房间筛选和选床提示隐藏。
2. OpenAPI与后端源码测试验证欢迎数据结构、确认接口、管理员配置接口和权限。
3. 数据库测试验证迁移、默认配置、扩展偏好、字段约束和固化结构。
4. 真实接口冒烟覆盖：管理员更新欢迎语及旧版本冲突、激活学生、首次登录返回欢迎、重复确认幂等、再次登录不再强制展示。
5. 个人偏好接口冒烟覆盖20项完整设置和新增7个关键代码。
6. 前端生产构建、后端全模块构建和现有第一、第二阶段流程必须全部通过。
