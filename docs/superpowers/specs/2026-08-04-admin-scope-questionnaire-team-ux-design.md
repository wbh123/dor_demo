# 管理员范围、问卷与组队体验改造设计

## 目标

在不改变现有选寝核心状态机的前提下，修复管理员录入、批次范围、住宿调整、问卷保存和组队邀请中的交互与业务缺陷，并增强严格导入模板的说明与值级容错。

## 总体方案

1. 前端新增可复用的手机号地区码选择器和三秒通知组件，避免各页面重复实现。
2. 学生住宿调整不再通过遍历所有批次的床位分配结果推断，而由后端提供学生当前在住和可用目标床位上下文，并使用在住事务完成跨寝室调整。
3. 批次范围接口直接返回活动互斥锁信息和禁选原因；页面继续保留现有专业、年级、楼栋、楼层筛选，并补充冲突标签。
4. 问卷保存兼容数据库驱动返回的布尔型、数字型和字符串型必填标记，避免类型转换异常。
5. 组队邀请同时校验学号和姓名；首次邀请自动建立内部队伍；发起人可取消尚未接受的邀请。
6. 严格模板保持固定表头，不恢复历史宽松表头；容错仅作用于单元格值，所有规范化和拒绝原因在预检中可见。

## 前端交互

### 手机号地区码

- 收起状态只展示 `+86` 这类地区码。
- 展开列表展示“国家或地区名称 + 地区码”。
- 修改国籍时自动同步默认地区码。
- 用户可在同步后单独选择其他地区码，直到国籍再次变化。

### 学生资料卡片

- 国内生/国际生切换放在表单最上方。
- 专业卡片和学生卡片使用相同高度；卡片主体采用弹性布局，列表、表单和操作区共同填满容器。
- 手机号、国家或地区等字段在桌面端保持两列，窄屏降为单列。

### 三秒通知

- 成功类业务提示统一显示为右上角浮层。
- 默认三秒自动消失，支持手动关闭。
- 失败信息仍保留在页面上下文中，避免错误被短暂提示掩盖。

### 批次范围

- 筛选输入和下拉固定高度，不随结果数量拉伸。
- 学生支持关键词、性别、国内外类别、培养层次、专业、年级筛选及当前结果全选。
- 宿舍支持关键词、性别、学生类别、楼栋、楼层筛选及当前可用结果全选。
- 被其他活动批次锁定的房间禁选，并显示冲突批次名称和“选择寝室/选择床位”标签。

## 后端业务

### 住宿调整

新增管理员学生住宿调整上下文与提交接口：

- 上下文返回学生当前有效在住、当前房间和符合性别、学生类别、运行状态及占用约束的目标床位。
- 提交在事务内结束旧在住并建立新在住，保留审计原因。
- 没有当前在住时返回稳定业务错误，不再静默无反应。

### 问卷保存

必填标记通过统一转换函数处理：

- `Boolean`：直接使用；
- `Number`：非零为真；
- `String`：`true` 或非零数字为真；
- 其他值为假。

### 组队邀请

- 邀请请求必填学号和姓名。
- 两者必须匹配同一位当前批次可邀请学生；错误信息不区分“学号存在但姓名错误”和“不存在”，避免信息探测。
- 首次邀请时若发起人没有队伍，服务自动建立内部队伍。
- 新增取消待处理邀请接口，仅队长且队伍处于组建中可操作。

## 模板与容错

学生模板包含：学号、姓名、性别、专业编码、国家或地区代码、学生类别、培养层次、年级、手机号。宿舍模板包含：楼栋编码、楼栋名称、楼层、房间号、房型、容量、性别、学生类别、运行状态、备注。

工作簿至少包含：

- `填写说明`：必填/选填、允许值、示例、预检与提交机制；
- `数据填写`：固定严格表头；
- `国家地区代码`：代码、中文名称、手机地区码；
- `字段枚举`：性别、类别、培养层次、房型、运行状态等允许值。

值级容错：去除首尾空格和全角空格；中文/英文枚举映射；国家或地区支持代码、中文名和英文名；年级支持 `2026` 与 `2026级`；手机号去除空格、短横线和括号，并结合国籍补全地区码。无法唯一推断的值必须在预检中报错，不猜测写入。

## 验证

- 跨层静态契约覆盖全部用户要求。
- Java 单元测试覆盖问卷布尔标记、邀请姓名校验、首次邀请自动建队、取消邀请和导入值规范化。
- 前端生产构建验证组件、接口类型和页面模板。
- 公开仓库持续集成通过后，基于私有最新 `main` 逐文件迁移，不复制数据库结构或私有文档到公开仓库。
